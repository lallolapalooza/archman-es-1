NOMBRE

PDF::Builder::Content - Métodos para agregar gráficos y texto a un PDF

Hereda de PDF::Builder::Basic::PDF::Dict

SINOPSIS

# Empezar con una página PDF (nueva o abierta)
my $pdf = PDF::Builder->new();
my $page = $pdf->page();
# Agregar nuevos objetos de contenido
my $content = $page->graphics();  # o gfx()
#   y/o (como nombre de objeto separado)
my $content = $page->text();
# Luego llamar a los métodos a continuación para agregar gráficos y texto a la página.
# ¡Tenga en cuenta que las coordenadas negativas pueden tener efectos impredecibles,
# así que mantenga sus coordenadas no negativas!

Estos métodos agregan contenido a los *streams* de salida para objetos de texto o gráficos. A menos que se restrinja explícitamente por una verificación de si estamos dentro o fuera del modo de texto, muchos de los métodos listados aquí se aplican igualmente a los streams de texto y gráficos. Es posible que existan algunos que no tengan efecto en un tipo de stream u otro, pero que actualmente carezcan de una verificación para evitar que se inserten en un stream inaplicable.

MÉTODOS

Todos los métodos públicos listados, *excepto cuando se indique lo contrario*, devuelven $self, para facilitar el encadenamiento de llamadas.

Transformaciones de Coordenadas

Los métodos en esta sección cambian el sistema de coordenadas para el objeto de contenido actual en relación con el resto del documento. **Nota:** los cambios son relativos a las coordenadas originales de la página (y por lo tanto, absolutas), ¡no a la posición anterior! Por lo tanto, "translate(10, 10); translate(10, 10);" termina moviendo solo el origen a "[10, 10]", en lugar de a "[20, 20]". Hay una llamada, transform_rel(), que hace que sus cambios sean *relativos* a la posición anterior.

Si llama a más de uno de estos métodos, la especificación PDF recomienda llamarlos en el siguiente orden: trasladar, rotar, escalar, distorsionar. Cada cambio se basa en el anterior, y puede obtener resultados inesperados al llamarlos en un orden diferente.

**PRECAUCIÓN:** un objeto de *texto* ($content) se comporta de manera un poco diferente. Las llamadas individuales de trasladar, rotar, escalar y distorsionar *cancelan* cualquier configuración previa. Si desea combinar múltiples transformaciones para texto, use la llamada "transform".

translate

$content->translate($dx,$dy)
Mueve el origen a lo largo de los ejes x e y a $dx y $dy respectivamente.

rotate

$content->rotate($grados)
Rota el sistema de coordenadas en sentido antihorario alrededor del origen actual. Use un argumento negativo para rotar en sentido horario. Tenga en cuenta que 360 grados se tratarán como 0 grados.

**Nota:** A menos que ya haya movido (trasladado) el origen, este está, y seguirá estando, en la esquina inferior izquierda de la hoja visible. *No* se desplazará automáticamente a otra esquina. Por ejemplo, una rotación de +90 grados (antihorario) dejará toda la hoja visible en el territorio Y negativo (0 en el borde izquierdo, -ancho_original en el borde derecho), mientras que X permanece en territorio positivo (0 en la parte inferior, +alto_original en el borde superior).

Esta llamada rotate() permite cualquier ángulo. No la confunda con la llamada de *rotación de página* "rotate", que solo permite incrementos de 90 grados (¡con signo opuesto!), pero *sí* desplaza el origen a otra esquina de la hoja.

scale

$content->scale($sx,$sy)
Escala (estira) los sistemas de coordenadas a lo largo de los ejes x e y. Se proporcionan multiplicadores separados para x e y.

skew

$content->skew($skx,$sky)
Distorsiona el sistema de coordenadas por $skx grados (antihorario) desde el eje x *y* $sky grados (horario) desde el eje y. Tenga en cuenta que 360 grados se tratarán igual que 0 grados.

transform

$content->transform(%opts)
Use una o más de las %opts dadas: 
$content->transform(
    'translate' => [$dx,$dy],
    'rotate'    => $grados,
    'scale'     => [$sx,$sy],
    'skew'      => [$skx,$sky],
    'matrix'    => [$a, $b, $c, $d, $e, $f],
    'point'     => [$x,$y]
    'repeat'    => $booleano
)

Se puede proporcionar una lista de seis elementos ("matrix") para una matriz de transformación adicional:

$a = cos(rot) * factor de escala para X 
$b = sin(rot) * tan(distorsión para X)
$c = -sin(rot) * tan(distorsión para Y)
$d = cos(rot) * factor de escala para Y 
$e = traslación para X
$f = traslación para Y

Realiza múltiples transformaciones de coordenadas en una sola llamada, en el orden recomendado por la especificación PDF (trasladar, rotar, escalar, distorsionar). Esto es equivalente a hacer cada transformación por separado, *en el orden indicado*. También se puede proporcionar una matriz de 6 valores ("matrix"). La matriz de transformación se actualiza. Se puede proporcionar un "point" (un punto que será multiplicado [transformado] por la matriz completada). Las opciones omitidas no cambiarán.

Si "repeat" es verdadero, y si esta no es la primera llamada a un método de transformación, la transformación anterior se repetirá, modificada por los otros argumentos proporcionados.

transform_rel

$content->transform_rel(%opts)
Realiza transformaciones de manera similar a "transform", excepto que *agrega* a los valores previamente establecidos, en lugar de *reemplazarlos* (excepto para *scale*, que *multiplica* los nuevos valores por los antiguos).

A diferencia de "transform", "matrix" y "point" no son compatibles.

matrix

$content->matrix($a, $b, $c, $d, $e, $f)
(Avanzado) Establece la matriz de transformación actual manualmente. A menos que tenga una necesidad particular de ingresar transformaciones manualmente, debe usar el método "transform" en su lugar. 
$a = cos(rot) * factor de escala para X 
$b = sin(rot) * tan(distorsión para X)
$c = -sin(rot) * tan(distorsión para Y)
$d = cos(rot) * factor de escala para Y 
$e = traslación para X
$f = traslación para Y

En modo de texto, se devuelve la matriz de texto. En modo gráfico, se devuelve $self.

Parámetros del Estado Gráfico

Las siguientes llamadas también afectan el estado del *texto*.

linewidth, line_width

$content->linewidth($ancho)
Establece el ancho del trazo (en puntos). Esta es la línea dibujada en modo gráfico, o el *contorno* de un carácter en modo de texto (con el modo "render" apropiado). Si no se proporciona $ancho, se devuelve la configuración actual. Si se está estableciendo el ancho, se devuelve $self para que las llamadas puedan encadenarse.

**Nombre alternativo:** "line_width"

Esto se proporciona para compatibilidad con PDF::API2.

linecap, line_cap

$content->linecap($estilo)
Establece el estilo que se utilizará al final de un trazo. Esto se aplica a las líneas que terminan libremente, *no* a las "uniones" ("esquinas") en polilíneas (ver "linejoin").

**Nombre alternativo:** "line_cap"

Esto se proporciona para compatibilidad con PDF::API2.

"butt" o "b" o 0 = Extremo de Línea Recto (por defecto)
El trazo termina en el final del camino, sin proyección.
"round" o "r" o 1 = Extremo de Línea Redondo
Se dibuja un arco semicircular alrededor del final del trazo con un diámetro igual al ancho de la línea, y se rellena.
"square" o "s" o 2 = Extremo de Línea Cuadrado Proyectado
El trazo continúa más allá del final del camino por la mitad del ancho de la línea.

Si no se proporciona $estilo, se devuelve la configuración actual. Si se está estableciendo el estilo, $self se devuelve para que las llamadas puedan encadenarse.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

set, $self se devuelve para que las llamadas puedan encadenarse.

Se puede proporcionar un número o una cadena (sin distinción entre mayúsculas y minúsculas).

linejoin, line_join

$content->linejoin($style)
Establece el estilo de unión a usar en las esquinas de un trazado (dentro de una polilínea de múltiples segmentos).

Nombre alternativo: "line_join"

Esto se proporciona para compatibilidad con PDF::API2.

"miter" o "m" o 0 = Unión de inglete, por defecto
Los bordes exteriores de los trazos se extienden hasta que se encuentran, hasta el límite especificado por miterlimit. Si se supera el límite, se utiliza una unión de bisel en su lugar. Para un ancho de línea dado, cuanto más agudo sea el ángulo (más cercano a 0 grados), mayor será la relación entre la longitud del inglete y el ancho de línea, y eso es lo que controla miterlimit: una unión muy "puntiaguda" se reemplaza por un bisel.
"round" o "r" o 1 = Unión redondeada
Se dibuja un círculo relleno con un diámetro igual al linewidth alrededor del punto de la esquina, produciendo una esquina redondeada. El arco se unirá a los lados de la línea con una tangente suave.
"bevel" o "b" o 2 = Unión biselada
Se dibuja un triángulo relleno para tapar la muesca entre los dos trazos.

Si no se proporciona ningún $style, se devuelve la configuración actual. Si se está estableciendo el estilo, se devuelve $self para que las llamadas puedan encadenarse.

Se puede proporcionar un número o una cadena (sin distinción entre mayúsculas y minúsculas).

miterlimit, miter_limit

$content->miterlimit($ratio)
Establece el límite de inglete cuando el estilo de unión de línea es un unión de inglete.

La relación es la longitud máxima del inglete (esquina interior a exterior) dividida por el ancho de la línea. Cualquier inglete por encima de esta relación se convertirá en una unión de bisel. El efecto práctico es que las líneas que se unen en ángulos poco profundos se cortan en lugar de producir esquinas largas y puntiagudas.

El límite de inglete por defecto es 10.0 (aproximadamente un ángulo de corte de 11.5 grados). Cuanto menor sea el límite, mayor será el ángulo de corte.

Si no se proporciona ninguna $ratio, se devuelve la configuración actual. Si se está estableciendo la relación, se devuelve $self para que las llamadas puedan encadenarse.

Nombre alternativo: "miter_limit"

Esto se proporciona para compatibilidad con PDF::API2. Hace mucho tiempo, en una galaxia lejana, este método se llamó erróneamente meterlimit, pero eso se eliminó hace tiempo. ¡Cualquier código que use ese nombre debe actualizarse!

linedash, line_dash_pattern

$content->linedash()
$content->linedash($length)
$content->linedash($dash_length, $gap_length, ...)
$content->linedash('pattern' => [$dash_length, $gap_length, ...], 'shift' => $offset)
Establece el patrón de guiones de línea.

Si se llama sin argumentos, se dibujará una línea sólida.

Si se llama con un argumento, los guiones y los espacios tendrán longitudes iguales.

Si se llama con dos o más argumentos, los argumentos representan longitudes alternas de guiones y espacios.

Si se llama con una tabla hash de argumentos, la matriz pattern puede tener uno o más elementos, especificando las longitudes de guion y espacio. Se puede establecer una fase de guion (shift), que es un entero positivo que especifica la distancia dentro del patrón en la que comenzar la línea discontinua. Tenga en cuenta que si desea proporcionar una cantidad de shift, usando "shift", debe usar "pattern" en lugar de uno o dos elementos.

Si se proporcionan un número impar de elementos en la matriz de guiones, el lector repetirá la lista para formar un número par de elementos (pares).

Si se proporciona un único argumento de -1, se devuelve la configuración actual. Es una matriz que consta de dos elementos: una matriz anónima que contiene el patrón de guiones (por defecto: vacía) y la cantidad de desplazamiento (offset) (por defecto: 0). Se puede utilizar directamente en una llamada a linedash(), ya que linedash reconocerá el patrón especial [ matriz, número ].

Si se está estableciendo el patrón de guiones, se devuelve $self para que las llamadas puedan encadenarse.

Nombre alternativo: "line_dash_pattern"

Esto se proporciona para compatibilidad con PDF::API2.

flatness, flatness_tolerance

$content->flatness($tolerance)
(Avanzado) Establece la variación máxima en píxeles de salida al dibujar curvas. El rango definido de $tolerance es de 0 a 100, donde 0 significa usar la planitud predeterminada del dispositivo. Según la especificación PDF, no debe intentar forzar segmentos de línea visibles (la aproximación de la curva); los resultados serán impredecibles. Por lo general, los resultados para diferentes configuraciones de planitud serán indistinguibles a la vista.

El valor $tolerance se ajusta silenciosamente para que esté entre 0 y 100.

Si no se proporciona ninguna $tolerance, se devuelve la configuración actual. Si se está estableciendo la tolerancia, se devuelve $self para que las llamadas puedan encadenarse.

Nombre alternativo: "flatness_tolerance"

Esto se proporciona para compatibilidad con PDF::API2.

egstate

$content->egstate($object)
(Avanzado) Añade un objeto de Estado Gráfico Extendido que contiene parámetros de estado adicionales.

Construcción de Trazados (Dibujo)

move

$content->move($x,$y)
Inicia un nuevo trazado en las coordenadas especificadas. Tenga en cuenta que se pueden proporcionar múltiples pares x,y, aunque esto no es muy útil (solo el último par tendría efecto).

close

$content->close()
Cierra y finaliza el trazado actual extendiendo una línea desde la posición actual hasta la posición de inicio.

Construcciones de línea recta

Nota: Ninguna de estas será realmente visible hasta que llame a "stroke", "fill" o "fillstroke". Simplemente están configurando el trazado para dibujar.

line

$content->line($x,$y)
$content->line($x,$y, $x2,$y2,...)
Extiende el trazado en una línea desde las coordenadas actuales hasta las coordenadas especificadas, y actualiza la posición actual a las nuevas coordenadas.

Se permiten múltiples pares adicionales de "[$x,$y]", para dibujar segmentos de línea múltiples y unidos. Tenga en cuenta que esto no es equivalente a una polilínea (ver "poly"), porque el primer par "[$x,$y]" en una polilínea es una operación de mover. Además, la configuración de "linecap" se utilizará en lugar de la configuración de "linejoin" para tratar los extremos de los segmentos.

hline, vline

$content->hline($x)
$content->vline($y)
Atajos para dibujar líneas horizontales y verticales desde la posición actual. Son como line(), pero a la nueva x y la y actual ("hline"), o a la x actual y la nueva y ("vline").

polyline

$content->polyline($x1,$y1, ..., $xn,$yn)
Este es un atajo para crear un trazado de polilínea desde la posición actual. Extiende el trazado en segmentos de línea a lo largo de las coordenadas especificadas. La posición actual se cambia a la última pareja "[$x,$y]" dada.

Una distinción crítica entre el método "polyline" y el método "poly" es que en este ("polyline"), el primer par de coordenadas se trata como una orden de dibujar (a diferencia de la orden de mover en "poly").

Por lo tanto, aunque esto se proporciona para compatibilidad con PDF::API2, ¡no es realmente un alias o nombre alternativo para "poly"!

poly

$content->poly($x1,$y1, ..., $xn,$yn)
Este es un atajo para crear un trazado de polilínea. Se mueve a "[$x1,$y1]", y luego extiende el trazado en segmentos de línea a lo largo de las coordenadas especificadas. La posición actual se cambia a la última pareja "[$x,$y]" dada.

La diferencia entre una polilínea y una "line" con múltiples pares "[$x,$y]" es que el primer par en una polilínea es un mover, mientras que en una línea es un dibujar. Además, se utiliza "line_join" en lugar de "line_cap" para controlar la apariencia de los extremos de los segmentos de línea.

Una distinción crítica entre el método "polyline" y el método "poly" es que en este ("poly"), el primer par de coordenadas se trata como una orden de mover.

rectangle

$content = $content->rectangle($x1, $y1, $x2, $y2)
Crea un nuevo trazado con forma de rectángulo, entre los dos puntos de esquina "[$x1, $y1]" y "[$x2, $y2]". Los puntos de esquina se intercambian si es necesario, para que "1" sea la inferior izquierda y "2" la superior derecha (x2 > x1 e y2 > y1). El objeto (aquí, $content) se devuelve, para permitir el encadenamiento.

Tenga en cuenta que esto no es un alias o nombre alternativo para "rect". Maneja solo un rectángulo, y toma coordenadas de esquina para la esquina "2", en lugar del ancho y la altura.

rect

$content = $content->rect($x,$y, $w,$h)
$content = $content->rect($x1,$y1, $w1,$h1, ..., $xn,$yn, $wn,$hn)
Esto crea trazados para uno o más rectángulos, con sus puntos inferiores izquierdos en "[$x,$y]" y anchos especificados (+dirección x) y alturas (+dirección y). Se permiten anchos y alturas negativos, que dibujan hacia la izquierda (-x) y hacia abajo (-y) del punto de esquina dado, respectivamente. La posición actual se cambia a la "[$x,$y]"

This section describes the methods available for constructing graphical paths in PDF::API2. These methods set up the path to be drawn, but do not render it themselves. Rendering is achieved by calling methods such as "stroke", "fill", or "fillstroke".

Note that in all cases where a new path is begun, the current position is advanced to the last point specified. If the path is being extended from an existing path, the current position is not explicitly changed unless specified by the method (e.g. for "arc").

Rectangular path constructs

rectangle

$content->rectangle($x1,$y1, $x2,$y2)
This creates a rectangular path with opposite corners at "[$x1,$y1]" and "[$x2,$y2]". The arguments are interpreted as the lower-left and upper-right corners, respectively. The current position is advanced to the last corner specified.

Note that this differs from the "rectxy" method in that the points must be specified in lower-left and upper-right order.

rect

$content->rect($x, $y, $width, $height)
This creates a rectangular path whose lower-left corner is at "[$x,$y]", and whose width and height are specified by $width and $height. The current position is advanced to the lower-left corner of the last rectangle given. Note that this is the starting point of the rectangle, not the end point. The object (here, $content) is returned, to permit chaining.

Note that this differs from the "rectangle" method in that multiple rectangles may be drawn in one call, and the second pair for each rectangle are the width and height, not the opposite corner coordinates.

rectxy

$content->rectxy($x1,$y1, $x2,$y2)
This creates a rectangular path, with "[$x1,$y1]" and "[$x2,$y2]" specifying opposite corners. They can be Lower Left and Upper Right, or Upper Left and Lower Right, in either order, so long as they are diagonally opposite each other. The current position is changed to the "[$x1,$y1]" (first) pair.

This is not quite an alias or alternate name for "rectangle", as it permits the corner points to be specified in any order.

Curved line constructs

Note: None of these will actually be visible until you call "stroke", "fill", or "fillstroke". They are merely setting up the path to draw.

circle

$content->circle($xc,$yc, $radius)
This creates a circular path centered on "[$xc,$yc]" with the specified radius. It does not change the current position.

ellipse

$content->ellipse($xc,$yc, $rx,$ry)
This creates a closed elliptical path centered on "[$xc,$yc]", with axis radii (semidiameters) specified by $rx (x axis) and $ry (y axis), respectively. It does not change the current position.

arc

$content->arc($xc,$yc, $rx,$ry, $alpha,$beta, $move, $dir)
$content->arc($xc,$yc, $rx,$ry, $alpha,$beta, $move)
This extends the path along an arc of an ellipse centered at "[$xc,$yc]". The semidiameters of the elliptical curve are $rx (x axis) and $ry (y axis), respectively, and the arc sweeps from $alpha degrees to $beta degrees. The current position is then set to the endpoint of the arc.

Set $move to a true value if this arc is the beginning of a new path instead of the continuation of an existing path. Either way, the current position will be updated to the end of the arc. Use "$rx == $ry" for a circular arc.

The optional $dir arc sweep direction defaults to 0 (false), for a counter-clockwise/anti-clockwise sweep. Set to 1 (true) for a clockwise sweep.

pie

$content->pie($xc,$yc, $rx,$ry, $alpha,$beta, $dir)
$content->pie($xc,$yc, $rx,$ry, $alpha,$beta)
Creates a pie-shaped path from an ellipse centered on "[$xc,$yc]". The x-axis and y-axis semidiameters of the ellipse are $rx and $ry, respectively, and the arc sweeps from $alpha degrees to $beta degrees. It does not change the current position. Depending on the sweep angles and direction, this can draw either the pie "slice" or the remaining pie (with slice removed). Use "$rx == $ry" for a circular pie. Use a different "[$xc,$yc]" for the slice, to offset it from the remaining pie.

The optional $dir arc sweep direction defaults to 0 (false), for a counter-clockwise/anti-clockwise sweep. Set to 1 (true) for a clockwise sweep.

This is a shortcut to draw a section of elliptical (or circular) arc and connect it to the center of the ellipse or circle, to form a pie shape.

curve

$content->curve($cx1,$cy1, $cx2,$cy2, $x,$y)
This extends the path in a curve from the current point to "[$x,$y]", using the two specified control points to create a cubic Bezier curve, and updates the current position to be the new point ("[$x,$y]").

Within a text object, the text's baseline follows the Bezier curve.

Note that while multiple sets of three "[x,y]" pairs are permitted, these are treated as independent cubic Bezier curves. There is no attempt made to smoothly blend one curve into the next!

qbspline, spline

$content->qbspline($cx1,$cy1, $x,$y)
This extends the path in a curve from the current point to "[$x,$y]", using the two specified points to create a quadratic Bezier curve, and updates the current position to be the new point.

Internally, these splines are one or more cubic Bezier curves (see "curve") with the two control points synthesized from the two given points (a control point and the end point of a quadratic Bezier curve).

Note that while multiple sets of two "[x,y]" pairs are permitted, these are treated as independent quadratic Bezier curves. There is no attempt made to smoothly blend one curve into the next!

Further note that this "spline" does not match the common definition of a spline being a continuous curve passing through all the given points! It is a piecewise non-continuous cubic Bezier curve. Use with care, and do not make assumptions about splines for you or your readers. You may wish to use the "bspline" call to have a continuously smooth spline to pass through all given points.

Pairs of points (control point and end point) are consumed in a loop. If one point or coordinate is left over at the end, it is discarded (as usual practice for excess data to a routine). There is no check for duplicate points or other degeneracies.

Alternate name: "spline"

This method is still named "spline" in PDF::API2, so for compatibility, that name is usable here. Since there are both quadratic and cubic splines available in PDF, it is preferred to use more descriptive names such as "qbspline" and "cbspline" to minimize confusion.

bspline, cbspline

$content->bspline($ptsRef, %opts)
This extends the path in a curve from the current point to the end of a list of coordinate pairs in the array referenced by $ptsRef. Smoothly continuous cubic Bezier splines are used to create a curve that passes through all the given points. Multiple control points are synthesized; they are not supplied in the call. The current position is updated to the last point.

Internally, these splines are one cubic Bezier curve (see "curve") per pair of input points, with the two control points synthesized from the tangent through each point as set by the polyline that would connect each point to its neighbors. The intent is that the resulting curve should follow reasonably closely a polyline that would connect the points, and should avoid any major excursions. See the discussions below for the handling of the control points at the endpoints (current point and last input point). The point at the end of the last line or curve drawn becomes the new current point.

Options %opts:

'firstseg' => 'mode'
where mode is
curve
This is the default behavior. This forces the first segment (from the current point to the first given point) to be drawn as a cubic Bezier curve. This means that the direction of the curve coming off the current point is unconstrained (it will end up being a reflection of the tangent at the first given point).
line1
This forces the first segment (from the current point to the first given point) to be drawn as a curve, with the tangent at the current point to be constrained as parallel to the polyline segment.
line2
This forces the first segment (from the current point to the first given point) to be drawn as a line segment. This also sets the tangent through the first given point as a continuation of the line, as well as constraining the direction of the line at the current point.
constraint1
This forces the first segment (from the current point to the first given point) to not be drawn, but to be an invisible curve (like mode=line1) to leave the tangent at the first given point unconstrained. A move will be made to the first given point, and the current point is otherwise ignored.
constraint2
This forces the first segment (from the current point to the first given point) to not be drawn, but to be an invisible line (like mode=line2) to constrain the tangent at the first given point. A move will be made to the first given point, and the current point is otherwise ignored.
'lastseg' => 'mode'
where mode is
curve

Esto extiende la ruta a lo largo de un arco de círculo del radio especificado entre "[$x1,$y1]" y "[$x2,$y2]". La posición actual se establece entonces en el punto final del arco ("[$x2,$y2]").

Establezca $move en un valor verdadero si este arco es el comienzo de una nueva ruta en lugar de la continuación de una ruta existente. Tenga en cuenta que el valor predeterminado ($move = false) no es una línea recta hacia P1 y luego el arco, sino una fusión en la curva desde el punto actual. ¡A menudo no pasará por P1!

Establezca $larger en un valor verdadero para dibujar el arco más grande ("exterior") entre los dos puntos, en lugar del más pequeño. Ambos arcos se dibujan en sentido horario desde P1 a P2. El valor predeterminado de false dibuja el arco más pequeño. Tenga en cuenta que se utiliza el arco más grande del otro círculo (el punto central se "invierte" a través de la línea entre P1 y P2), en lugar de usar el "resto" del círculo del arco más pequeño (lo que requeriría invertir la dirección del recorrido a lo largo del arco -- ver $reverse).

Establezca $reverse en un valor verdadero para dibujar la imagen especular del arco especificado (voltéelo, de modo que su punto central esté en el otro lado de la línea que conecta los dos puntos). Ambos arcos se dibujan en sentido antihorario desde P1 a P2. El valor predeterminado (false) dibuja arcos en sentido horario. Un arco se dibuja siempre de P1 a P2; se puede elegir la dirección (horaria o antihoraria).

El valor de $radius no puede ser menor que la mitad de la distancia desde "[$x1,$y1]" a "[$x2,$y2]". Si es demasiado pequeño, el radio se establecerá en la mitad de la distancia entre los puntos (lo que resultará en un arco que es una semicircunferencia). Este es un error silencioso, ya que incluso si los puntos son correctos, debido al redondeo, etc., puede que no caigan exactamente en los dos círculos.

Puede pensar en ello como "mirar" desde P1 a P2. En el caso degenerado, donde el radio es exactamente la mitad de la distancia entre los puntos, no hay diferencia entre los arcos "pequeño" y "grande", y ambos círculos coincidirán con su centro a mitad de camino entre P1 y P2. Solo importa la dirección. Una vez que el radio es un poco mayor, los dos círculos se vuelven distintos. El círculo principal está centrado a su derecha, cuyo arco pequeño es en sentido horario a su izquierda; el círculo secundario está centrado a su izquierda, cuyo arco pequeño es en sentido antihorario a su derecha. Los arcos "grandes" son los arcos que usan el resto de los círculos: el gran arco horario es parte del círculo izquierdo (secundario) y el gran arco antihorario es parte del círculo derecho (principal).

Texto

Parámetros de estado del texto

Todos los siguientes parámetros que toman un tamaño se aplican antes de que ocurra cualquier escalado, por lo que no necesita ajustar los valores para contrarrestar el escalado.

charspace, character_spacing, char_space

$spacing = $content->charspace($spacing)
Establece espaciado horizontal adicional entre caracteres en una línea. Los sistemas de escritura vertical no están soportados. Esto está en *puntos* y está inicialmente en cero. Puede ser positivo para dar un efecto *expandido* a las palabras, o puede ser negativo para dar un efecto *condensado* a las palabras. Si se proporciona $spacing, la configuración actual se reemplaza por ese valor y se devuelve $self (para permitir el encadenamiento). Si no se proporciona $spacing, se devuelve la configuración actual.

Un uso para el espaciado de caracteres es ajustar el *tracking* en una línea de texto. Es común ajustar el espaciado entre palabras (por ejemplo, la longitud del "pegamento" de TeX) para justificar una línea (ver "wordspace"), pero en casos donde el resultado es que las palabras están demasiado juntas (o demasiado separadas), puede querer ajustar el tracking para forzar los espacios a un tamaño estándar más "razonable". Por ejemplo, si tiene una línea bastante "suelta", con espacios amplios entre palabras, podría añadir un poco de espaciado de caracteres entre las letras de las palabras, y reducir los espacios a un tamaño más razonable. ¡No lo exagere y haga que las palabras sean difíciles de leer! También querrá tener cuidado de "impulsar" los espacios resultantes hacia un ancho consistente en todo un documento (o al menos, un párrafo).

También puede optar por utilizar el espaciado de caracteres para efectos especiales, como un encabezado de alto nivel expandido con espacio adicional. Este es un efecto decorativo y debe usarse con moderación.

¡Tenga en cuenta que los espacios entre palabras (x20) *también* reciben espaciado de caracteres adicional, además de cualquier espaciado entre palabras adicional ("wordspace") definido!

PRECAUCIÓN: tenga cuidado al usar "charspace" si está utilizando una fuente conectada ("script"). Esto podría incluir árabe, devanagari, escritura cursiva latina, etc. No querrá dejar huecos entre caracteres, o causar solapamientos. Para tales fuentes y tipos de letra, *puede* que necesite establecer explícitamente el espaciado de "charspace" a 0, si lo ha establecido a un valor distinto de cero en otro lugar. PDF::Builder puede no ser capaz de determinar que una fuente dada es una fuente de script conectada, y suprimir automáticamente el espaciado de caracteres no nulo.

Nombres alternativos: "character_spacing" y "char_space"

character_spacing se proporciona para compatibilidad con PDF::API2, mientras que char_space se proporciona para ser coherente con muchos otros cambios de nombres de métodos en PDF::API2.

wordspace, word_spacing, word_space

$spacing = $content->wordspace($spacing)
Establece espaciado horizontal adicional entre palabras en una línea. Los sistemas de escritura vertical no están soportados. Esto está en *puntos* y está inicialmente en cero (es decir, solo el ancho del espacio, sin nada extra). Puede ser negativo para juntar un poco las oraciones. Si se proporciona $spacing, la configuración actual se reemplaza por ese valor y se devuelve $self (para permitir el encadenamiento). Si no se proporciona $spacing, se devuelve la configuración actual.

Consulte la nota en "charspace" con respecto al ajuste de *tracking*, y su efecto en "wordspace". Las dos llamadas a menudo se pueden usar juntas para obtener resultados óptimos (aunque resultando en un tamaño de archivo PDF algo mayor).

Tenga en cuenta que es una limitación de la especificación PDF (según la versión 1.7, sección 9.3.3) que solo se ajusta el espaciado con un espacio ASCII (x20). Ni los espacios requeridos (xA0) ni los espacios multibyte (incluidos espacios finos y anchos) se ajustan actualmente. Sin embargo, los espacios *múltiples* entre palabras se expanden *cada uno*. Por ejemplo, si tiene un espacio x20 doble entre palabras, ¡recibirá *el doble* de la expansión de un solo espacio! Además, el espaciado de caracteres (Tc) también se añade a cada espacio, *además* del espaciado entre palabras (Tw).

Nombres alternativos: "word_spacing" y "word_space"

word_spacing se proporciona para compatibilidad con PDF::API2, mientras que word_space se proporciona para ser coherente con muchos otros cambios de nombres de métodos en PDF::API2.

hscale

$scale = $content->hscale($scale)
Establece el porcentaje de escalado horizontal del texto (tamaño relativo, *no* espaciado). Inicialmente es 100 (por ciento, es decir, sin escalado). Una escala mayor que 100 estirará el texto, mientras que menor que 100 lo comprimirá. Si se proporciona $scale, la configuración actual se reemplaza por ese valor y se devuelve $self (para permitir el encadenamiento). Si no se proporciona $scale, se devuelve la configuración actual.

Tenga en cuenta que el escalado afecta a todos los anchos de caracteres, espaciado entre letras y espaciado entre palabras. Es desaconsejable estirar o comprimir texto en gran medida, ya que rápidamente lo hará ilegible. Si su objetivo es justificar texto, generalmente será mejor usar "charspace" y "wordspace" para expandir (o condensar ligeramente) una línea para llenar un ancho deseado. Consulte también las llamadas text_justify() para este propósito.

Si se proporciona $leading, la configuración actual se reemplaza por ese valor y se devuelve $self (para permitir el encadenamiento). Si no se proporciona $leading, se devuelve la configuración actual.

Tenga en cuenta que el *leading* aquí se define como se usa en la composición electrónica y la especificación PDF, que es el espaciado interlínea completo (distancia de línea base a línea base de texto, en puntos). En la composición tipográfica en metal, el *leading* era generalmente el espaciado *adicional* entre líneas más allá de la altura de la fuente en sí, creado insertando cuñas de plomo (aleación tipográfica).

Movement and Positioning Methods

These methods are used to position text on the PDF page. Many are analogous to methods in PDF::API2, and are provided for compatibility.

distance

$content->distance($dx,$dy)

Moves to the start of the previously-written line, plus an offset by the given amounts, which are both required. "0,0" would overwrite the previous line, while "0,36" would place the new line 36pt above the old line (higher y). The $dx moves to the right, if positive.

"distance" is analogous to graphic's "move", except that it is relative to the beginning of the previous text write, not to the coordinate origin. Note that subsequent text writes will be relative to this new starting (left) point and Y position! E.g., if you give a non-zero $dx, subsequent lines will be indented by that amount.

cr

$content->cr()
$content->cr($vertical_offset)
$content->cr(0)

If passed without an argument, moves (down) to the start of the next line (distance set by "leading"). This is similar to nl().

If passed with an argument, the "leading" distance is ignored and the next line starts that far up the page (positive value) or down the page (negative value) from the current line. "Y" increases upward, so a negative value would normally be used to get to the next line down.

An argument of 0 would simply return to the start of the present line, overprinting it with new text. That is, it acts as a simple carriage return, without a linefeed.

Note that any setting for "leading" is ignored. If you wish to account for the "leading" setting, you may wish to use the "crlf" method instead.

nl

$content->nl()
$content->nl($indent)
$content->nl(0)

Moves to the start of the next line (see "leading"). If $indent is not given, or is 0, there is no indentation. Otherwise, indent by that amount (outdent if a negative value). The unit of measure is hundredths of a "unit of text space", or roughly 88 per em.

Note that any setting for "leading" is ignored. If you wish to account for the "leading" setting, you may wish to use the "crlf" method instead.

crlf

$content = $content->crlf()

Moves to the start of the next line, based on the "leading" setting. It returns its own object, for ease of chaining.

If leading isn't set, a default distance of 120% of the font size will be used.

Added for compatibility with PDF::API2 changes; may be used to replace both "cr" and "nl" methods.

$width = $content->advancewidth($string, %opts)

Returns the number of points that will be used (horizontally) by the input string. This assumes all on one line (no line breaking).

Options: %opts:

'font' => $f3_TimesRoman
Change the font used, overriding $self->{' font'}. The font must have been previously created (i.e., is not the name). Example: use Times-Roman.
'fontsize' => 12
Change the font size, overriding $self->{' fontsize'}. Example: 12 pt font.
'wordspace' => 0.8
Change the additional word spacing, overriding $self->wordspace(). Example: add 0.8 pt between words.
'charspace' => -2.1
Change the additional character spacing, overriding $self->charspace(). Example: subtract 2.1 pt between letters, to condense the text.

Note that these values temporarily replace the existing values, not scaling them up or down. For example, if the existing charspace is 2, and you give in options a value of 3, the value used is 3, not 5.

Note: This does not affect the PDF in any way. It only tells you how much horizontal space a text string will take up.

This is provided for compatibility with PDF::API2.
