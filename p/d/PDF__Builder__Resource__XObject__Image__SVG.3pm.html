NOMBRE

PDF::Builder::Resource::XObject::Image::SVG - Rutinas de soporte para la biblioteca de imágenes SVG (Scalable Vector Graphics)

Hereda de PDF::Builder::Resource::XObject::Image

Tenga en cuenta que, a diferencia de la salida de otros formatos de imagen, "image_svg()" devuelve una matriz de hashes anónimos, uno por cada etiqueta <svg> dentro de la entrada SVG. Vea "Qué se devuelve" a continuación para obtener detalles.

MÉTODOS

new

$res = PDF::Builder::Resource::XObject::Image::SVG->new($pdf, $file, %opts)

$file proporciona la entrada SVG (consulte la biblioteca SVGPDF para obtener detalles y limitaciones). Puede ser un nombre de archivo, una referencia de cadena (con contenido SVG) o un manejador de archivos.

Opciones:
subimage => n
Si hay varias entradas "svg" en un archivo SVG, y no se combinan mediante la opción "combine" de SVGPDF en una sola imagen, esto permite seleccionar qué imagen mostrar. Se puede proporcionar cualquier n, desde 0 hasta el número de imágenes "svg" menos 1. Se conservará el n-ésimo elemento y se desecharán todos los demás. El valor predeterminado es devolver toda la matriz y no eliminar ningún elemento, lo que permite mostrar varias imágenes en el orden deseado. Consulte la discusión sobre la combinación de varias imágenes "Manejo de varios objetos de imagen y su combinación". El comportamiento predeterminado de la rutina de visualización ("object") es mostrar solo el primer elemento (debe haber al menos uno).
MScore => flag
Si se establece en verdadero (un valor distinto de cero), se agregará una devolución de llamada de fuente para las 14 extensiones "principales" de Microsoft Windows a cualquier otra devolución de llamada de fuente proporcionada por el usuario. Estas incluyen fuentes serif "Georgia", sans-serif "Verdana" y "Trebuchet", y fuentes de simbología "Wingdings" y "Webdings". Los sistemas que no son de Windows generalmente no incluyen estas fuentes "principales", por lo que puede no ser seguro usarlas.

Esta opción está habilitada para todos los sistemas operativos, no solo para MS Windows, por lo que puede crear PDF que utilicen las fuentes "principales" de Windows (extensión). ¡Esto no garantiza que dichas fuentes *estarán* disponibles en la máquina utilizada para leer el PDF resultante!

compress => flag
Si se establece en verdadero (un valor distinto de cero; el valor predeterminado es 1), la transmisión XObject resultante se comprimirá. Esto es lo que normalmente haría. Por otro lado, establecerlo en falso (0) deja la transmisión sin comprimir. Es posible que desee hacer esto si desea examinar la transmisión en el PDF finalizado, como se hace para la prueba t.

Opciones de SVGPDF:

Estas son opciones que, si se proporcionan, se pasan a la biblioteca SVGPDF. Algunas de ellas están fijadas por "image_svg" y no se pueden cambiar, mientras que otras tienen valores predeterminados por "image_svg" pero *pueden* ser anuladas por el usuario.

Debería consultar la documentación de la biblioteca SVGPDF para obtener más detalles sobre dichas opciones.

pdf => Objeto PDF
Esto se establece automáticamente mediante la rutina SVG y el usuario **no** puede anularlo. Se pasa a "SVGPDF->new()".
fontsize => n
Este es el tamaño de fuente (en puntos) que SVGPDF utilizará para escalar texto y calcular los tamaños de em y ex. El valor predeterminado es 12 puntos. Se pasa tanto a los métodos SVGPDF "SVGPDF->new()" como a "$svg->process()".
pagesize => [ ancho, alto ]
Estas son las dimensiones máximas del objeto resultante, en caso de que no se proporcionen dimensiones o sean demasiado grandes para mostrarlas. El valor predeterminado es 595 pt x 842 pt (tamaño de página A4), interno de SVGPDF. Se pasa a "SVGPDF->new()".
grid => n
El valor predeterminado es 0. Un valor mayor que 0 indica el espaciado (en puntos) de una cuadrícula para fines de desarrollo/depuración. Se pasa a "SVGPDF->new()".
verbose => n
Por defecto es 0 (solo mensajes fatales), pero el usuario puede establecerlo en un valor más alto para mostrar mensajes informativos. Se pasa a "SVGPDF->new()".
fc => \&callback_manejador_fuente
Esta es una lista de una o más devoluciones de llamada para el manejador de fuentes. Si la bandera "MScore" es verdadera (ver arriba), se agregará otra devolución de llamada a la lista para manejar las caras de fuente "principales" de MS Windows. Se pasa a "SVGPDF->new()".

Tenga en cuenta que algunos paquetes de soporte, como GnuPlot, utilizan fuentes de Windows como Arial, que pueden o no estar instaladas en plataformas no Windows, e incluso para Windows, necesitarían agregarse a FontManager. Debería comprobar los archivos SVG resultantes producidos por paquetes de terceros para ver qué fuentes esperan. MathJax crea caracteres de texto como contornos rellenos en SVG y no parece utilizar ninguna fuente estándar.

combine => 'método'
Si hay varios XObjects definidos por un SVG (debido a múltiples entradas "svg"), pueden combinarse en un solo XObject. El valor predeterminado es none, que *no* combina XObjects. Actualmente, el único otro método compatible es stacked, que apila imágenes verticalmente, con "sep" de espaciado entre ellas. En el momento de escribir esto, el método de combinación bbox *no* es compatible con SVGPDF, pero puede serlo en el futuro. Se pasa a "$svg->process()".
sep => n
Espacio vertical (en puntos) para agregar entre imágenes individuales cuando "combine" no es 'none'. El valor predeterminado es 0 (sin espacio entre imágenes). Se pasa a "$svg->process()".

Qué se devuelve

Devuelve una imagen en SVG. A diferencia de otros formatos de imagen, en realidad *no* es algún tipo de objeto de imagen, sino una matriz (de al menos un elemento) que contiene XObjects de la SVG convertida a comandos gráficos y de texto de PDF. Si una SVG incluye una imagen basada en píxeles, esa imagen se escalará hacia arriba y hacia abajo de la forma habitual, mientras que los gráficos y el texto de PDF siempre serán completamente escalables, tanto al establecer un tamaño de imagen *como* al acercar y alejar en un lector de PDF.

Un "objeto" devuelto es siempre una matriz de hashes (incluido el XObject como uno de los elementos), uno por etiqueta "svg". Tenga en cuenta que las "svg" deben ser pares (de nivel superior) y *no* pueden anidarse una dentro de otra. En la mayoría de las aplicaciones, un archivo SVG tendrá una etiqueta "svg" y, por lo tanto, un solo elemento en la matriz. Sin embargo, algunas SVG producirán varios elementos de matriz a partir de múltiples etiquetas "svg".

Manejo de varios objetos de imagen y su combinación

Si no establece "subimage", se devolverá la matriz completa. Si establece "subimage => n", donde n es un número de elemento válido (0...), todos los elementos *excepto* el n-ésimo se desecharán, dejando una matriz de un solo elemento. Cuando llegue el momento de que object() muestre esta matriz de XObjects, se mostrará el primer elemento (0), y cualquier otro elemento se ignorará. Por lo tanto, el comportamiento predeterminado es efectivamente "subimage => 0". Puede llamar a "object" o "image", ya que "image" simplemente pasará todo a "object".
