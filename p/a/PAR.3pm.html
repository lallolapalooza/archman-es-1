NAME

PAR - Toolkit de Archivos Perl

SYNOPSIS

(Si deseas crear un ejecutable que contenga todos los módulos, scripts y archivos de datos, consulta el utility pp. El pp fue parte del distribución PAR antes, pero ahora se envía como parte de la distribución PAR::Packer.)

Ejemplos siguientes asumen un archivo foo.par en formato ZIP.

Para usar Hello.pm desde ./foo.par:

% perl -MPAR=./foo.par -MHello
% perl -MPAR=./foo -MHello          # el .par es opcional

Lo mismo, pero busca en foo.par dentro de @INC:

% perl -MPAR -Ifoo.par -MHello
% perl -MPAR -Ifoo -MHello          # lo mismo

Los caminos dentro del archivo PAR se buscan así:

/lib/
/arch/
/i386-freebsd/              # es decir, $Config{archname}
/5.8.0/                     # es decir, $Config{version}
/5.8.0/i386-freebsd/        # ambos de arriba
/

Los archivos dentro de un archivo PAR pueden también (recursivamente) contener otros archivos PAR. Todos los archivos bajo los siguientes caminos se consideran como archivos PAR y se buscan así:

/par/i386-freebsd/          # es decir, $Config{archname}
/par/5.8.0/                 # es decir, $Config{version}
/par/5.8.0/i386-freebsd/    # ambos de arriba
/par/

Ejecuta script/test.pl o test.pl desde foo.par:

% perl -MPAR foo.par test.pl        # solo cuando $0 termina en .par

Sin embargo, si el archivo .par contiene either script/main.pl o main.pl, se usará este último:

% perl -MPAR foo.par test.pl        # ejecuta main.pl; @ARGV es 'test.pl'

Usa en un programa:

use PAR 'foo.par';
use Hello; # lee dentro de foo.par
# PAR::read_file() devuelve un archivo dentro de cualquier PAR cargado
my $conf = PAR::read_file('data/MyConfig.yaml');
# PAR::par_handle() devuelve un objeto Archive::Zip
my $zip = PAR::par_handle('foo.par')
my $src = $zip->memberNamed('lib/Hello.pm')->contents;

También puedes usar caracteres de asterisco:

use PAR '/home/foo/*.par';  # carga todos los archivos PAR en ese directorio

Desde la versión 0.950, puedes usar una sintaxis diferente para cargar archivos .par:

use PAR { file => 'foo.par' }, { file => 'otherfile.par' };

¿Por qué? Porque puedes también hacer esto:

use PAR { file => 'foo.par, fallback => 1 };
use Foo::Bar;

Foo::Bar se buscará primero en las bibliotecas del sistema y se cargará desde foo.par si no lo encuentra!

use PAR { file => 'foo.par', run => 'myscript' };

Este cargará foo.par como usual y luego ejecutará el archivo script/myscript del archivo. Debe notar que tu programa no regresa al control. Cuando script/myscript se sale, así lo hace tu programa principal. Para hacerlo más útil, puedes deferir esto al runtime: (de lo contrario equivalente)

require PAR;
PAR->import( { file => 'foo.par', run => 'myscript' } );

Si tienes instalado PAR::Repository::Client, puedes hacer:

use PAR { repository => 'http://foo/bar/' };
use Module; # no está instalado localmente!

Y PAR cargará cualquier módulo que no tengas desde el repositorio especificado. Para más detalles sobre cómo funciona, ve el SECCIÓN DE NOTAS. En lugar de un URL o ruta local, puedes construir un objeto PAR::Repository::Client manualmente y pasarle a PAR. Si especificas la opción install => 1 en la línea use PAR anterior, el distribución que contiene Module se instalará permanentemente en tu sistema. ("use PAR { repository => 'http://foo/bar', install => 1 };")

Además, hay una opción "upgrade => 1" que verifica actualizaciones en el repositorio además de instalar. Por favor nota que una versión actualizada de un módulo solo se carga en el próximo ejecucion de tu aplicación.

La opción "dependencies => 1" habilita la resolución estática de dependencias de PAR::Repository::Client (PAR::Repository::Client 0.23 y versiones posteriores).

Finalmente, puedes combinar las opciones "run" y "repository" para ejecutar un programa directamente desde un repositorio! (También puedes especificar la opción "install".)

use PAR { repository => 'http://foo/bar/', run => 'my_app' };
# No llegará a este punto ya que ejecutaste my_app,

DESCRIPCIÓN

Este módulo te permite cargar módulos Perl especializados en archivos zip, llamados Perl Archivos, como bibliotecas desde las cuales se pueden cargar módulos Perl.

Soporta la carga de módulos XS sobrepues métodos de inicialización de DynaLoader; escribe un archivo de objeto compartido en un archivo temporal al momento de ser necesario.

Un archivo .par es principalmente un zip de la carpeta blib después del proceso de construcción de una distribución CPAN. Para generar un archivo .par tú mismo, solo tienes que comprimir los módulos en arch/ y lib/, por ejemplo:

% perl Makefile.PL
% make
% cd blib
% zip -r mymodule.par arch/ lib/

Después, puedes usar mymodule.par en cualquier lugar de tu @INC, usar PAR, y es simplemente funciona. La soporte para generar archivos .par está en la próxima (más de 0.2805) versión de Module::Build.

Para conveniencia, puedes establecer la variable entorno PERL5OPT a -MPAR para habilitar el procesamiento de PAR globalmente (el overhead es pequeño si no lo usas); establecerla a -MPAR=/path/to/mylib.par cargará un archivo específico de PAR. Alternativamente, considera usar el utility par.pl que viene con la distribución PAR::Packer, o usar el utility parl que también está distribuido con PAR::Packer en máquinas sin PAR.pm instaladas.

Nota: Los scripts y ejecutables self-contained creados con par.pl y pp también pueden usarse como archivos .par:

% pp -o packed.exe source.pl        # genera packed.exe (ver PAR::Packer)
% perl -MPAR=packed.exe other.pl    # también funciona
% perl -MPAR -Ipacked.exe other.pl  # lo mismo

Por favor, ve el SECCIÓN DE SYNOPSIS para casos típicos de uso.

NOTAS

Los ajustes en META.yml dentro del archivo PAR pueden afectar la operación de PAR. Por ejemplo, el pp proporciona la opción -C ("--clean") para controlar el comportamiento predeterminado de la creación de archivos temporales.

Actualmente, los archivos generados con pp pueden tener cuatro atributos específicos de PAR almacenados en META.yml:

par:
  clean: 0          # valor por defecto de PAR_CLEAN
  signature: ''     # clave ID del archivo SIGNATURE
  verbatim: 0       # ¿se preservaron los PODs de la dependencia previa?
  version: x.xx     # versión de PAR.pm que generó este PAR

Las variables de entorno definidas por el usuario, como PAR_GLOBAL_CLEAN, siempre sobreescanean las definidas en META.yml. El algoritmo para generar el caché/temporal se sigue así:

  • Si PAR_GLOBAL_TEMP es especificado, lo usa como directorio de caché para bibliotecas extraídas, y no lo limpia después de ejecutar.
  • Si no está especificado PAR_GLOBAL_TEMP, pero está especificado PAR_GLOBAL_CLEAN, establece PAR_GLOBAL_TEMP a "TEMP/par-USERHEX/temp-PID/", limpiándolo después de ejecutar.
  • Si ninguno de los dos es especificado, usa "TEMP/par-USERHEX/cache-HASH/" como PAR_GLOBAL_TEMP, reutilizando cualquier archivo existente dentro.

Aquí está una descripción de las variables mencionadas anteriormente.

  • TEMP es un directorio temporal, que puede ser establecido mediante $ENV{PAR_GLOBAL_TMPDIR}, $ENV{TMPDIR}, $ENV{TEMPDIR}, $ENV{TEMP} o $ENV{TMP}, en ese orden de prioridad. Si ninguno de estos es establecido, se examina C:\TEMP, /tmp y si ninguno de ellos existe, se usa .
  • USERHEX se deriva de el nombre del usuario, o SYSTEM si no se puede encontrar. En Win32, este es $Win32::LoginName

A continuación, se describe el comportamiento de las variables mencionadas anteriormente.

NAME

PAR - Perl Archive Format

SYNOPSIS

  # To pack files into a par file:
  perl par.pl -o Foo.par lib/Foo.pm lib/Foo/Bar.pm
  # To pack a directory into a par file:
  perl par.pl -r -o Foo.par lib/Foo/
  # To pack a perl script into a self-contained executable:
  perl par.pl -O -o foo foo.pl
  # To run a script in a par file:
  perl Foo.par
  # To unpack a par file:
  perl par.pl -x -r -o Foo.par
  # In code:
  use PAR;
  PAR->import( file => 'Foo.par' );
  # Or with a repository
  PAR->import( repository => 'http://foo/bar/' );
  use Foo; # loads Foo.pm from Foo.par

DESCRIPTION

PAR (Perl Archive Format) is a simple, efficient, and extensible archive format for packaging Perl scripts and modules. It is designed to simplify the deployment and distribution of Perl applications.

The par.pl script is the primary tool for creating, unpacking, and running PAR archives.

The PAR Perl module allows you to load modules from PAR archives at runtime. This is useful for distributing applications as single files or for managing dependencies.

NOTES

When PAR archives are executed directly (e.g. perl Foo.par), they create a temporary directory to unpack their contents. This temporary directory is named after the archive, prepended with a prefix derived from the username and process ID, and is typically created in the system's temporary directory (e.g. /tmp). You can control the location and naming of this temporary directory using the following environment variables:

  • PAR_ROOT: Specifies the root directory for temporary PAR archives. If not set, defaults to the system's temporary directory.
  • PAR_TEMP: Specifies the prefix for the temporary directory name. The default prefix is derived from the username and process ID.

The naming convention for the temporary directory is as follows:

PAR_ROOT/PAR-USERHEX-PID

Where:

  • USERHEX is the hexadecimal representation of the user's name. On Unix-like systems, this is typically derived from $ENV{USERNAME} or $ENV{USER}. Each raw byte of the username is encoded as two hexadecimal digits.
  • PID is the process ID. Child processes created by forking inherit the parent's PID for this purpose.
  • HASH is a cryptographic hash of the entire PAR file or executable, calculated at the time of creation. This value can be overridden using the --tempdir parameter of pp.

By default, PAR strips POD (Plain Old Documentation) sections from bundled modules. If this causes issues, you can disable this behavior by setting the environment variable PAR_VERBATIM to 1.

import options

When you use "use PAR {...}" or call PAR->import({...}), the following options are available.

PAR->import({ file => 'foo.par' });
# or
PAR->import({ repository => 'http://foo/bar/' });
file
The name of the PAR file. You must specify exactly one of either the 'file' or 'repository' option.
repository
A PAR repository URL (mutually exclusive with 'file').
fallback
When true, search the system @INC *before* the PAR archive or repository. This is the default behavior when loading PAR files via the "file =" option. When loading from a PAR repository, fallback is true by default. To prioritize loading modules from a repository over locally installed modules, set fallback => 0:

use PAR { repository => 'http://foo/bar/', fallback => 0 };
run
The name of a script within the PAR archive to execute. The program will exit after the script finishes.
no_shlib_unpack
Prevent PAR from unpacking bundled dynamic libraries from the shlib/$archname directory within the archive. This can be useful if the required libraries are already installed on the system or if you intend to manage their caching manually. The libraries must be accessible in a standard installation location (e.g., /usr/local/lib/) or in the directory specified by $ENV{PAR_TEMP} *before* the dependent module is required. Failure to do so will result in Perl dying with an error message like "cannot open shared object file..."
