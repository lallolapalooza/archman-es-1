PAR::Environment(3) Documentación de Perl aportada por el usuario PAR::Environment(3)

NOMBRE

PAR::Environment - Índice y referencia de variables de entorno de PAR

DESCRIPCIÓN

PAR utiliza varias variables de entorno tanto durante el proceso de construcción de ejecutables o archivos PAR como para su *uso*. Dado que la gran cantidad de combinaciones y configuraciones puede confundir a uno u otro (como a mí), este documento pretende documentar todas las variables de entorno que PAR utiliza.

Dondequiera que quiera referirme a la entrada del hash de entorno $ENV{FOO}, normalmente hablaré de la variable "FOO" por brevedad.

ÍNDICE DE VARIABLES DE ENTORNO

¡Tenga en cuenta que esto todavía está muy, muy incompleto! ¡Contribuciones bienvenidas!

Para cada variable, debería haber una descripción de lo que contiene, cuándo se puede esperar que exista (y contenga información significativa), cuándo es sensato definirla uno mismo y qué efecto tiene esto.

Por supuesto, la descripción puede usar ejemplos.

PAR_0

Si el programa en ejecución se ejecuta desde dentro de un archivo PAR o un ejecutable producido por pp, esta variable contiene el nombre del programa extraído (es decir, el archivo .pl). Esto es útil si desea abrir el archivo de código fuente del programa en ejecución.

Por ejemplo, si empaqueta un archivo foo.pl en bar.par y ejecuta foo.pl con este comando

par.pl foo.par bar.pl

entonces la variable "PAR_0" contendrá algo como "/tmp/par-youser/cache-b175f53eb731da9594e0dde337d66013ddf25a44/495829f0.pl" donde "youser" es su nombre de usuario y "/tmp/par-youser/cache-b175f53eb731da9594e0dde337d66013ddf25a44/" es el directorio de caché de PAR ("PAR_TEMP").

El nombre del directorio de caché de PAR puede adoptar una serie de formas diferentes, así que utilice "PAR_0" si desea encontrar el archivo .pl del programa extraído; intentar construir el nombre usted mismo requiere una lógica compleja que ya ha producido el valor en "PAR_0".

Esto funciona igual para archivos binarios ejecutables (.exe, ...).

Si busca el nombre y la ruta del archivo binario pp-ed, consulte la variable "PAR_PROGNAME".

PAR_CLEAN

Los usuarios deberían establecer "PAR_GLOBAL_CLEAN" en su lugar.

Recreado desde "PAR_GLOBAL_CLEAN" y el valor de "-C" del archivo YAML por el cargador PAR, y utilizado dentro del cargador para controlar el comportamiento inicial de extracción y el comportamiento final de limpieza. El usuario puede hacer referencia a "PAR_CLEAN" en la aplicación para determinar cuál de estos comportamientos se está utilizando para esta ejecución de la aplicación.

PAR_DEBUG

Los usuarios deberían establecer "PAR_GLOBAL_DEBUG" en su lugar.

Si esta variable se establece en un valor verdadero y se ejecuta par.pl, se envía salida detallada a STDOUT o al manejador de registro. Esto se anula por la opción "-q" de par.pl, para los pasos posteriores a la análisis de argumentos.

Esto actualmente solo influye en par.pl. Si este es el comportamiento previsto aún está por verificar.

PAR_GLOBAL_CLEAN

Establecer "PAR_GLOBAL_CLEAN" altera el comportamiento de las aplicaciones PAR que ven esa variable de entorno al iniciarse. "PAR_GLOBAL_CLEAN" anula la opción "-C". Se admiten los valores 0 y 1. 0 corresponde a no usar "-C" en la línea de comandos de pp; 1 corresponde a usar "-C" en la línea de comandos de pp. "PAR_GLOBAL_CLEAN" se ignora si se establece "PAR_GLOBAL_TEMP", sin embargo, controla la forma de "PAR_TEMP" cuando no se establece "PAR_GLOBAL_TEMP".

PAR_GLOBAL_DEBUG

El cargador PAR se vuelve más detallado cuando se establece "PAR_DEBUG". Establecer "PAR_GLOBAL_DEBUG" garantiza que "PAR_DEBUG" se establecerá internamente, inicialmente. Consulte "PAR_DEBUG" para más detalles.

PAR_GLOBAL_TEMP

Contribuye al cálculo de "PAR_TEMP", y se explica más adelante.

PAR_GLOBAL_TMPDIR

Contribuye al cálculo de "PAR_TEMP", y se explica más adelante.

PAR_INITIALIZED

Esta variable de entorno es solo para uso interno del cargador binario de PAR. Documentada solo para evitar sorpresas si las aplicaciones generadas esperan ver un valor inicializado por el usuario.

PAR_PROGNAME

"PAR_PROGNAME" se establece en el nombre de ruta completo del programa ejecutable. En Windows, esto se obtiene de manera confiable de la API "GetModuleFileName". En otros sistemas operativos, si el tiempo de ejecución de C recibe un nombre de ruta calificado, se utiliza, o el nombre de archivo no calificado dado se califica recorriendo la ruta. Esto es razonablemente confiable dadas las convenciones normales de generación de programas, pero no se puede garantizar que sea correcto en todas las circunstancias.

PAR_APP_REUSE

Estrictamente interno. Omita esta sección si no es un desarrollador de PAR.

La variable nunca debería exponerse al código del usuario y las aplicaciones empaquetadas no deberían depender de que esté establecida o no.

Si una aplicación ha sido empaquetada con la opción "--reusable", el código de arranque establecerá esta variable de entorno con el nombre del programa que se va a ejecutar en lugar del programa empaquetado. El script cargador main.pl recupera el nombre del archivo, elimina la variable de entorno y luego ejecuta el programa dado.

PAR_RUN

Esta variable de entorno se estableció durante la construcción de objetos "PAR::Packer" (generalmente solo durante las ejecuciones de pp) por versiones de PAR hasta 0.957. Desde PAR 0.958, esta variable no se utiliza.

PAR_SPAWNED

Esta variable es utilizada internamente por el cargador binario parl para indicar al proceso hijo que es el hijo.

No debe depender de esta variable fuera del código del cargador binario de PAR. Para una discusión un poco más detallada, consulte el archivo de documentación who_am_i.txt en la distribución fuente de PAR, que fue aportado por Alan Stewart.

Documentada solo para evitar sorpresas si las aplicaciones generadas esperan ver un valor inicializado por el usuario.

PAR_TEMP

Los usuarios deberían establecer "PAR_GLOBAL_TEMP" en su lugar. "PAR_TEMP" se calcula a partir de una variedad de otras variables. Consulte la sección "NOTAS" en el pod de PAR.pm para obtener una descripción completa de cómo procede el cálculo. "PAR_TEMP", una vez calculado, se utiliza como la ubicación donde PAR almacena su caché de archivos extraídos y temporales.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

PAR_TMPDIR

Añade parte al cálculo de "PAR_TEMP", y se explica más allí. Los usuarios deben establecer "PAR_GLOBAL_TMPDIR" en su lugar.

PAR_VERBATIM

La variable "PAR_VERBATIM" controla cómo el código Perl se empaqueta en un archivo PAR o binario ejecutable. Si se establece un valor verdadero durante el proceso de empaquetado, los módulos (y scripts) no se pasan por el filtro predeterminado "PAR::Filter::PodStrip", que elimina toda la documentación POD del código. Debe recordarse que el filtro "PAR::Filter::PatchContent" todavía se aplica.

La opción "-F" del programa pp anula el valor de "PAR_VERBATIM". Esto significa que si estableces "PAR_VERBATIM=1" pero especificas "-F PodStrip" en la línea de comandos de "pp", el filtro "PodStrip" se aplicará.

"PAR_VERBATIM" no es utilizado por el programa PAR.

PAR_VERBOSE

Establecer esta variable de entorno como un número positivo tiene el mismo efecto que usar la opción "-verbose" del programa pp.

PP_OPTS

Durante una ejecución de pp, el contenido de la variable "PP_OPTS" se trata como si fuera parte de la línea de comandos. En versiones más recientes de PAR, también puedes escribir las opciones en un archivo y ejecutar pp de la siguiente manera para leer las opciones del archivo:

pp @FILENAME

Esto puede combinarse con otros argumentos de línea de comandos para pp o con la variable "PP_OPTS".

TMP, TEMP, TMPDIR, TEMPDIR

Por favor, consulta "PAR_TMPDIR".
