PAR::Dist(3) Documentación de Perl aportada por el usuario PAR::Dist(3)

NOMBRE

PAR::Dist - Crear y manipular distribuciones PAR

SINOPSIS

Como comando de shell:

% perl -MPAR::Dist -eblib_to_par

En programas:

use PAR::Dist;
my $dist = blib_to_par(); # crea un archivo PAR usando ./blib/
install_par($dist);       # lo instala en el sistema
uninstall_par($dist);     # lo desinstala del sistema
sign_par($dist);          # lo firma usando Module::Signature
verify_par($dist);        # lo verifica usando Module::Signature
install_par("http://foo.com/DBI-1.37-MSWin32-5.8.0.par"); # también funciona
install_par("http://foo.com/DBI-1.37"); # añade automáticamente el nombre de arquitectura + versión de perl
install_par("cpan://SMUELLER/PAR-Packer-0.975"); # usa el directorio de autor de CPAN

DESCRIPCIÓN

Este módulo crea y manipula distribuciones PAR. Son archivos PAR específicos de la arquitectura, que contienen todo lo que hay bajo blib/ de las distribuciones CPAN después de su etapa de "make" o "Build", un META.yml que describe los metadatos de la distribución CPAN original y un MANIFEST que detalla todos los archivos dentro de ella. Las distribuciones PAR firmadas digitalmente también contendrán un archivo SIGNATURE.

La convención de nombres para tales distribuciones es:

$NOMBRE-$VERSION-$ARQ-$PERL_VERSION.par

Por ejemplo, "PAR-Dist-0.01-i386-freebsd-5.8.0.par" corresponde al lanzamiento 0.01 de "PAR-Dist" en CPAN, construido para perl 5.8.0 ejecutándose en "i386-freebsd".

FUNCIONES

Varias funciones se exportan por defecto. A menos que se indique lo contrario, pueden tomar un hash de argumentos nombrados, un solo argumento (tomado como $path por "blib_to_par" y $dist por otras funciones), o ningún argumento (en cuyo caso se usa el primer archivo PAR en el directorio actual).

Por lo tanto, bajo un directorio que contenga solo un único test.par, todas las invocaciones a continuación son equivalentes:

% perl -MPAR::Dist -e"install_par( dist => 'test.par' )"
% perl -MPAR::Dist -e"install_par( 'test.par' )"
% perl -MPAR::Dist -einstall_par;

Si $dist se parece a una URL, se llama a "LWP::Simple::mirror" para reflejarla localmente bajo $ENV{PAR_TEMP} (o "$TEMP/par/" si no se especifica), y la función actuará sobre el archivo local obtenido en su lugar. Si la URL comienza con "cpan://AUTHOR/", se expandirá automáticamente al directorio CPAN del autor (por ejemplo, "http://www.cpan.org/modules/by-authors/id/A/AU/AUTHOR/").

Si $dist no tiene una extensión de archivo que comience con una letra o guion bajo, se le añadirá un guion y $suffix ($ARCH-$PERL_VERSION.par por defecto).

blib_to_par

Toma pares clave/valor como parámetros o un solo parámetro que indica la ruta que contiene el subdirectorio blib/.

Construye una distribución PAR a partir del subdirectorio blib/ bajo "path", o bajo el directorio actual si no se especifica. Si blib/ no existe, ejecuta automáticamente Build, make, Build.PL o Makefile.PL para crearlo.

Devuelve el nombre de archivo de la distribución PAR generada.

Los parámetros válidos son:

path
Establece la ruta que contiene el subdirectorio blib/ desde el cual se generará la distribución PAR.
name, version, suffix
Estos atributos establecen el nombre, la versión y el sufijo específico de la plataforma de la distribución. El nombre y la versión se pueden determinar automáticamente a partir de los archivos META.yml o Makefile.PL de la distribución.

El sufijo se genera a partir de su nombre de arquitectura y su versión de perl por defecto.

dist
El nombre de archivo de salida para la distribución PAR.
quiet
Establecido a verdadero para suprimir la mayor cantidad de salida posible.

install_par

Instala una distribución PAR en el sistema, usando "ExtUtils::Install::install_default".

Si solo se da un parámetro, se trata como el valor para el parámetro "dist".

Los parámetros nombrados válidos son:

dist
El archivo .par a instalar. Se aplican las heurísticas descritas en la sección FUNCIONES.
prefix
Esta cadena se antepondrá a todas las rutas de instalación. Si no se especifica, la variable de entorno "PERL_INSTALL_ROOT" se usa como prefijo.
uninstall_shadows
Esto corresponde a la opción "uninstall_shadows" de ExtUtils::Install. Citando su manual: Si "uninstall_shadows" se establece en verdadero, se desinstalarán las versiones diferentes en @INC. Esto es "make install UNINST=1".
verbose
Esto corresponde a la opción "verbose" de ExtUtils::Install. Según su manual: Si "verbose" es verdadero, imprimirá cada archivo eliminado. Esto es "make install VERBINST=1". Los valores de "verbose" hasta 5 muestran cada vez más salida de diagnóstico.

La verbosidad por defecto para PAR::Dist es 1.

Si solo va a instalar en el perl en ejecución como todo lo demás, puede dejar de leer el resto de esta sección ahora.

Además, puede usar varios parámetros para cambiar los destinos de instalación predeterminados. Normalmente no tiene que preocuparse por esto a menos que esté instalando en un directorio local del usuario. La siguiente sección describe los nombres de los parámetros y la configuración predeterminada:

Parámetro         Desde          A
inst_lib          blib/lib      $Config{installsitelib} (*)
inst_archlib      blib/arch     $Config{installsitearch}
inst_script       blib/script   $Config{installscript}
inst_bin          blib/bin      $Config{installbin}
inst_man1dir      blib/man1     $Config{installman1dir}
inst_man3dir      blib/man3     $Config{installman3dir}
packlist_read                   $Config{sitearchexp}/auto/$name/.packlist
packlist_write                  $Config{installsitearch}/auto/$name/.packlist

El parámetro "packlist_write" se usa para controlar dónde se escribe el archivo .packlist. (Necesario para la desinstalación). El parámetro "packlist_read" especifica un archivo .packlist para fusionar si existe. Al establecer cualquiera de los objetivos de instalación anteriores en "undef", puede eliminar ese objetivo por completo. Por ejemplo, pasar "inst_man1dir => undef, inst_man3dir => undef" significa que las páginas de manual contenidas no se instalarán. Esto no está disponible para las listas de paquetes.

Nuevamente, los valores predeterminados serán las rutas site normales de %Config.

(*) Si la sección inst_archlib del ".par" (normalmente "blib/arch") no está vacía, el código en inst_lib (normalmente "blib/lib") también se instala en la ruta inst_archlib. Esto tiene sentido para los módulos XS. Si, sin embargo, anula "inst_lib", ¡esta conversión automática también se anula! Puede usar el parámetro nombrado "auto_inst_lib_conversion => 1" para volver a habilitar la conversión para inst_lib personalizados.

Finalmente, puede especificar un "custom_targets"

PAR::Dist(3pm) — Arch Linux

NAME

PAR::Dist - Utilities for manipulating PAR archives

SYNOPSIS

    use PAR::Dist;
    use PAR::Dist::Install qw(install_par);
    use ExtUtils::Install qw(install);

    # Install all files to blib/
    install_par('MyModule-0.01.par');

    # Install files to blib/ with custom targets
    install_par(
        'MyModule-0.01.par',
        custom_targets => { 'blib/my_data' => '/some/path/my_data' }
    );

    # Uninstall a previously installed PAR archive
    uninstall_par('MyModule-0.01.par');

    # Sign a PAR archive
    sign_par('MyModule-0.01.par');

    # Verify a PAR archive signature
    verify_par('MyModule-0.01.par');

    # Merge PAR archives
    merge_par('foo.par', 'bar.par', 'baz.par');

    # Remove man pages from a PAR archive
    remove_man(dist => 'MyModule-0.01.par');

    # Extract META.yml from a PAR archive
    my $meta = get_meta(dist => 'MyModule-0.01.par');

    # Parse distribution name
    my ($name, $version, $arch, $perl) = parse_dist_name('MyModule-0.01-x86_64-linux.par');

    # Create a stub for a new PAR distribution
    generate_blib_stub(name => 'MyApp', version => '1.00');
    
    # Check if a PAR contains binaries
    if (contains_binaries('MyModule-0.01.par')) {
        # Handle binary distribution
    }

DESCRIPTION

This module provides a set of utilities for manipulating PAR archives. It is designed to be used by packagers, distributors, and anyone else who needs to work with PAR files.

It provides functions for installing and uninstalling PAR archives, signing and verifying them, merging multiple archives into one, and extracting metadata. It also includes helper functions for creating new PAR distributions from scratch.

FUNCTIONS

install_par

Installs the contents of a PAR distribution into the "blib" directory using "ExtUtils::Install::install". It supports installing to custom locations via the "install_root" and "destdir" parameters, and can also install files to arbitrary locations using the "custom_targets" parameter.

The function takes the PAR archive name as the first argument, followed by a list of named parameters:

"install_root"
Specifies the root directory for the installation. Defaults to the current directory.
"destdir"
Specifies a destination directory prefix. Files will be installed relative to this directory. Defaults to undef.
"overwrite_files"
A boolean value. If true, existing files will be overwritten. Defaults to true.
"verbose"
A boolean value. If true, installation progress will be printed to STDOUT. Defaults to false.
"dry_run"
A boolean value. If true, no files will be actually installed, but the process will be simulated. Defaults to false.
"custom_targets"
This parameter expects a hash reference of custom installation targets. Its value should be a reference to a hash of custom installation targets such as

custom_targets => { 'blib/my_data' => '/some/path/my_data' }

You can use this to install the .par archives contents to arbitrary locations.

uninstall_par

Uninstalls all previously installed contents of a PAR distribution, using "ExtUtils::Install::uninstall".

Takes almost the same parameters as "install_par", but naturally, the installation target parameters do not apply. The only exception to this is the "packlist_read" parameter which specifies the .packlist file to read the list of installed files from. It defaults to "$Config::Config{installsitearch}/auto/$name/.packlist".

Additionally, the "uninstall_shadows" parameter of "install_par" isn't available.

sign_par

Digitally sign a PAR distribution using "gpg" or Crypt::OpenPGP, via Module::Signature.

verify_par

Verify the digital signature of a PAR distribution using "gpg" or Crypt::OpenPGP, via Module::Signature.

Returns a boolean value indicating whether verification passed; $! is set to the return code of "Module::Signature::verify".

merge_par

Note: Since version 0.32 of PAR::Dist, this function requires a YAML reader. The order of precedence is:

YAML:XS YAML YAML::Syck YAML::Tiny

Merges two or more PAR distributions into one. First argument must be the name of the distribution you want to merge all others into. Any following arguments will be interpreted as the file names of further PAR distributions to merge into the first one.

merge_par('foo.par', 'bar.par', 'baz.par')

This will merge the distributions "foo.par", "bar.par" and "baz.par" into the distribution "foo.par". "foo.par" will be overwritten!

The original META.yml of "foo.par" is retained, but augmented with any "provides", "requires", "recommends", "build_requires", and "configure_requires" sections from the other ".par" files.

remove_man

Remove the man pages from a PAR distribution. Takes one named parameter: dist which should be the name (and path) of the PAR distribution file. The calling conventions outlined in the "FUNCTIONS" section above apply.

The PAR archive will be extracted, stripped of all "man\d?" and "html" subdirectories and then repackaged into the original file.

get_meta

Opens a PAR archive and extracts the contained META.yml file. Returns the META.yml file as a string.

Takes one named parameter: dist. If only one parameter is passed, it is treated as the dist parameter. (Have a look at the description in the "FUNCTIONS" section above.)

Returns undef if no PAR archive or no META.yml within the archive were found.

parse_dist_name

First argument must be a distribution file name. The file name is parsed into distribution name, distribution version, architecture name, and perl version.

Returns the results as a list in the above order. If any or all of the above cannot be determined, returns undef instead of the undetermined elements.

Supported formats are:

Math-Symbolic-0.502-x86_64-linux-gnu-thread-multi-5.8.7

Math-Symbolic-0.502

The ".tar.gz" or ".par" extensions as well as any preceding paths are stripped before parsing. Starting with "PAR::Dist" 0.22, versions containing a preceding "v" are parsed correctly.

This function is not exported by default.

generate_blib_stub

Creates a blib/lib subdirectory in the current directory and prepares a META.yml with meta information for a new PAR distribution. First argument should be the name of the PAR distribution in a format understood by parse_dist_name(). Alternatively, named arguments resembling those of "blib_to_par" are accepted.

After running "generate_blib_stub" and injecting files into the blib directory, you can create a PAR distribution using "blib_to_par". This function is useful for creating custom PAR distributions from scratch. (I.e. not from an unpacked CPAN distribution) Example:

use PAR::Dist;
use File::Copy 'copy';
generate_blib_stub(
  name => 'MyApp', version => '1.00'
);
copy('MyApp.pm', 'blib/lib/MyApp.pm');
blib_to_par(); # generates the .par file!

"generate_blib_stub" will not overwrite existing files.

contains_binaries

This function is not exported by default.

Opens a PAR archive tries to determine whether that archive contains platform-specific binary code.

Takes one named parameter: dist. If only one parameter is passed, it is treated as the dist parameter. (Have a look at the description in the "FUNCTIONS" section above.)

Throws a fatal error if the PAR archive could not be found.

Returns one if the PAR was found to contain binary code and zero otherwise.
