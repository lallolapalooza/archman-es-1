NOMBRE

Path::IsDev::Result - Contenedor de resultados

VERSIÓN

version 1.001003

SINOPSIS

use Path::IsDev::Result;
my $result = Path::IsDev::Result->new( path => '/alguna/ruta/que/existe' ):
if ( $heuristica->matches( $result ) ) {
    print Dumper($result);
}

DESCRIPCIÓN

Este es un componente interno relativamente nuevo para Path::IsDev.

Su propósito es comunicar el estado entre elementos internos y proporcionar algún tipo de contexto introspectivo sobre por qué ocurrieron las cosas en varios lugares, sin recurrir a inundar con depuración.

Ahora, en lugar de activar la depuración, siempre que puedas obtener un resultado, puedes inspeccionar y volcar ese resultado en el punto en que lo necesites.

MÉTODOS

"CONSTRUIR"

"añadir_razón"

Llama a este método desde una heurística para registrar la comprobación de la heurística y los metadatos relevantes.

$result->añadir_razón( $heurística, $valor_coincidencia, $resumen_razón, \%info_contexto );

Por ejemplo:

sub Foo::matches  {
    my ( $self , $objeto_resultado ) = @_;
    if ( $objeto_resultado->ruta->hijo('bar')->existe ) {
        $objeto_resultado->añadir_razón( $self, 1, "el hijo 'bar' existe", {
            hijo => 'bar',
            'existe?' => 1,
            ruta_hijo => $objeto_resultado->ruta->hijo('bar')
        });
        $objeto_resultado->resultado(1);
        return 1;
    }
    return;
}

Nota que aquí, $valor_coincidencia debe ser el resultado de la lógica de coincidencia relevante, no el impacto global.

Por ejemplo, las composiciones de "excluye" todavía deberían añadir razones de "$valor_coincidencia == 1", pero no deberían establecer "$objeto_resultado->resultado(1)". ( De hecho, establecer "resultado" es trabajo de la heurística individual, no de las coincidencias que se integran en ella )
