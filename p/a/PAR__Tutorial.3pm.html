Sobre el despliegue de aplicaciones Perl

% sshnuke.pl 10.2.2.2 -rootpw="Z1ON0101"
Se requiere Perl v5.6.1 -- esto es solo v5.6.0, se detuvo en la línea 1 de sshnuke.pl.

  • P: "¡Ayuda! ¡No puedo ejecutar tu programa!"
  • R1: Instalar Perl y "perl -MCPAN -e 'install(...)'"
  • ¿Cómo sabemos qué módulos se necesitan?
  • Las nuevas versiones de los módulos CPAN pueden romper "sshnuke.pl"

R3: Usar el ejecutable generado por "perlcc sshnuke.pl"

PAR, el Kit de Archivos Perl

•
Hace lo que JAR (Java Archive) hace para Perl
  • Agrega módulos, scripts y otros archivos en un archivo Zip
  • Fácil de generar, actualizar y extraer
  • Consistencia de versiones: resuelve problemas de compatibilidad hacia adelante
  • Desarrollado por la comunidad: "par@perl.org"
•
Los archivos PAR se pueden empaquetar en scripts autocontenidos
  • Escanea automáticamente el script de Perl en busca de dependencias
  • Agrupa todos los módulos de terceros necesarios con él
  • Solo requiere Perl central para ejecutarse en la máquina de destino
  • PAR también viene con "pp", el Empaquetador Perl: 
    % pp -o sshnuke.exe sshnuke.pl # ¡ejecutable autocontenido!

Empaquetado Simple

  • Los archivos PAR son solo archivos Zip con módulos dentro
  • Cualquier herramienta Zip puede generarlos: 
    % zip foo.par Hello.pm World.pm        # empaqueta dos módulos
% zip -r bar.par lib/          # toma todos los módulos en lib/
  • Para cargar módulos desde archivos PAR: 
    use PAR;
use lib "foo.par";             # la parte .par es opcional
use Hello;
  • Esto también funciona: 
    use PAR "/home/mylibs/*.par";  # ponlos todos en @INC
use Hello;

Cargadores PAR

  • Usa "par.pl" para ejecutar archivos dentro de un archivo PAR: 
    % par.pl foo.par               # busca 'main.pl' por defecto
% par.pl foo.par test.pl       # ejecuta script/test.pl en foo.par
  • Lo mismo, con el "parl" o "parl.exe" autocontenido: 
    % parl foo.par                 # ¡no necesita perl ni PAR.pm!
% parl foo.par test.pl         # lo mismo
  • El cargador PAR puede anteponerse a un archivo PAR:
  • "-b" agrupa módulos no centrales necesarios para "PAR.pm": 
    % par.pl -b -O./foo.pl foo.par # script autocontenido
  • "-B" agrupa módulos centrales además de "-b": 
    % parl -B -O./foo.exe foo.par  # binario autocontenido

Escaneo de Dependencias

  • Escanea recursivamente las dependencias con "scandeps.pl": 
    % scandeps.pl sshnuke.pl
# Leyenda: [C]entral [X]terno [S]ubmódulo [?]NoEnCPAN
'Crypt::SSLeay'       => '0', #  X   #
'Net::HTTP'           => '0', #      #
'Crypt::SSLeay::X509' => '0', # S    # Crypt::SSLeay
'Net::HTTP::Methods'  => '0', # S    # Net::HTTP
'Compress::Zlib'      => '0', #  X   # Net::HTTP::Methods
  • Escanea una línea de un solo comando, lista todos los archivos involucrados: 
    % scandeps.pl -V -e "use Dynaloader;"
...
# auto/DynaLoader/dl_findfile.al [autoload]
# auto/DynaLoader/extralibs.ld [autoload]
# auto/File/Glob/Glob.bs [data]
# auto/File/Glob/Glob.so [shared]
...

Empaquetador Perl: "pp"

  • Combina escaneo, empaquetado zip y incrustación del cargador: 
    % pp -o out.exe src.pl         # .exe autocontenido
% out.exe                      # se ejecuta en cualquier lugar del mismo SO
  • Agrupa módulos adicionales: 
    % pp -o out.exe -M CGI src.pl  # empaqueta CGI + sus dependencias también
  • Empaqueta líneas de un solo comando: 
    % pp -o out.exe -e 'print "Hola"'   # convierte una línea de comando en ejecutable
  • Genera archivos PAR en lugar de ejecutables: 
    % pp -p src.pl                 # crea 'source.par'
% pp -B -p src.pl              # incluye módulos centrales

Cómo funciona

•
Las opciones de línea de comandos son casi idénticas a las de "perlcc"
•
También admite opciones largas estilo "gcc": 
% pp --gui --verbose --output=out.exe src.pl
  • Pequeña sobrecarga inicial; sin sobrecarga en tiempo de ejecución
  • Las dependencias se eliminan de la POD antes de empaquetar
  • Carga módulos directamente en memoria bajo demanda
  • Las bibliotecas compartidas (DLL) se extraen con File::Temp
  • Funciona en Perl 5.6.0 o superior
  • Probado en Win32 (VC++ y MinGW), FreeBSD, NetBSD, Linux, MacOSX, Cygwin, AIX, Solaris, HP-UX, Tru64...

Agregando múltiples programas

  • Una pregunta común: 
    > He usado pp para crear varias aplicaciones independientes que funcionan
> muy bien, el único problema es que por cada ejecutable que creo, asumo que
> parl.exe está de alguna manera incluido en el ejecutable resultante.
  • La solución obvia: 
    Puedes distribuir parl.exe por sí solo, junto con archivos .par creados
por "pp -p", y ejecutar esos archivos PAR asociándolos a parl.exe.
  • En plataformas que tienen "ln", hay una mejor solución: 
    % pp --output=a.out a.pl b.pl  # ¡dos scripts en uno!
% ln a.out b.out               # el enlace simbólico también funciona
% ./a.out                      # ejecuta a.pl
% ./b.out                      # ejecuta b.pl

Paquetes Multiplataforma

  • Por supuesto, no existe un formato binario multiplataforma
  • Los paquetes PAR puramente Perl son multiplataforma por defecto
  • Sin embargo, los módulos XS son específicos de la versión y plataforma de Perl
  • Múltiples versiones de un módulo XS pueden coexistir en un archivo PAR
  • Supongamos que necesitamos "out.par" tanto en Win32 como en Finix: 
    C:\> pp --multiarch --output=out.par src.pl
...copia src.pl y out.par a una máquina Finix...
% pp --multiarch --output=out.par src.pl
  • Ahora funciona en ambas plataformas: 
    % parl out.par                 # ejecuta src.p

PAR, un Archivo Perl

Los archivos PAR son un formato de empaquetado para aplicaciones Perl y sus módulos dependientes. Permiten empaquetar un script Perl y todas sus dependencias en un solo archivo, lo que facilita su distribución y ejecución.

Uso

  • Para empaquetar un script Perl llamado script.pl en un archivo PAR llamado out.par: 
    % pp -o out.par script.pl
  • Para empaquetar un script Perl y hacerlo ejecutable: 
    % pp -e out.par script.pl
% chmod a+x out.par
% ./out.par
  • Para ejecutar un script de un archivo PAR sin instalarlo: 
    % perl -MPAR=out.par -e '...'  # usa módulos dentro de out.par

La Anatomía de un archivo PAR

  • Los módulos pueden estar ubicados en varios directorios: 
    /                      # packing casual solo
/lib/                  # ubicación estándar
/arch/                 # para crear desde blib/
/i386-freebsd/         # por ejemplo, $Config{archname}
/5.8.0/                # por ejemplo, número de versión de Perl
/5.8.0/i386-freebsd/   # combinación de los dos anteriores
  • Los scripts se almacenan en uno de los dos lugares: 
    /                      # packing casual solo
/script/               # ubicación estándar
  • Las bibliotecas compartidas pueden ser específicas de arquitectura o versión de Perl: 
    /shlib/(5.8.0/)?(i386-freebsd/)?
  • Los archivos PAR pueden contener recursivamente otros archivos PAR: 
    /par/(5.8.0/)?(i386-freebsd/)?

Archivos especiales

•
MANIFEST
  • Índice de todos los archivos dentro del PAR
  • Puede ser parseado con "ExtUtils::Manifest"
•
META.yml
  • Dependencias, licencias, opciones de ejecución
  • Puede ser parseado con "YAML"
•
SIGNATURE
  • Signatura digital PGP abierta
  • Puede ser parseada y verificada con "Module::Signature"

Ventajas sobre perlcc, PerlApp y Perl2exe

•
Este no es un flame
•
Los tres mantenedores han contribuido directamente al PAR; agradecido
•
perlcc
  • "El código generado en este modo no está garantizado para funcionar... Se debe evitar su uso en producción." (de perldoc perlcc)
  • "No funciona garantizado" es más como lo dice
•
PerlApp / Perl2exe
  • Costoso: Se necesita pagar por cada actualización
  • No portable: Solo disponible en plataformas limitadas
  • Propietario: No puede extender sus características o corregir errores
  • Obfuscado: El proveedor y los ciberdelincuentes pueden ver su código, pero no puede
  • Inflexible: No funciona con instalaciones existentes de Perl

MANIFEST: Mejor visto con Mozilla

  • La URL del archivo MANIFEST dentro de "/home/autrijus/foo.par": 
    jar:file:///home/autrijus/foo.par!/MANIFEST
  • Abre en un navegador Gecko (por ejemplo, Netscape 6+) con JavaScript activo:
  • No se necesita descomprimir nada; simplemente haz clic en los archivos para verlos

META.yml: Metadatos galácticos

•
Metadatos estáticos y lectura máquina
•
Soportado por "Module::Build", "ExtUtils::MakeMaker", "Module::Install"
  • Un ejemplo típico de "pp"-generado "META.yml" parece así: 
    build_requires: {}
conflicts: {}
dist_name: out.par
distribution_type: par
dynamic_config: 0
generated_by: 'Perl Packager version 0.03'
license: unknown
par:
  clean: 0
  signature: ''
  verbatim: 0
  version: 0.68
  • Los par:" settings controlan su comportamiento de ejecución

SIGNATURE: Firmado y verificado de paquetes

•
Un mensaje PGP firmado con cálculos SHA1
•
Soportado por "Module::Signature", "CPANPLUS" y "Module::Build"
  • Un ejemplo típico de "SIGNATURE" parece así: 
    -----BEGIN PGP SIGNED MESSAGE-----
Hash: SHA1
SHA1 8a014cd6d0f6775552a01d1e6354a69eb6826046 AUTHORS
...
-----BEGIN PGP SIGNATURE-----
...
-----END PGP SIGNATURE-----
  • Usa "pp" y "cpansign" para trabajar con firmas: 
    % pp -s -o foo.par bar.pl      # crear y firmar foo.par a partir de bar.pl
% cpansign -s foo.par  # firmar este archivo PAR
% cpansign -v foo.par  # verificar este archivo PAR

Servlets de Perl con Apache::PAR

•
Framework para aplicaciones web self-contained
  • Similar a la arquitectura de aplicaciones web (WAR) de Java
  • Funciona con mod_perl 1.x o 2.x
•
Una aplicación web completa dentro de un archivo .par
  • Apache configuración, archivos estáticos, módulos Perl...
  • Soportado de Static, Registry y PerlRun handlers
  • Puede cargar todas las PARs en un directorio
•
Una archivo especial adicional: "web.conf" 
Alias /myapp/cgi-perl/ ##PARFILE##/
<Location /myapp/cgi-perl>
    Options +ExecCGI
    SetHandler perl-script
    PerlHandler Apache::PAR::Registry
</Location>

Hon Dah, A-par-che!

  • Primero, genera un "hondah.par" a partir de un línea única: 
    # use el "web.conf" de anterior
% pp -p -o hondah.par -e 'print "Hon Dah!\n"' \
     --add web.conf
% chmod a+x hondah.par
  • Añade esta a "httpd.conf", luego reinicia Apache: 
    <IfDefine MODPERL2>
PerlModule Apache2
</IfDefine>
PerlAddVar PARInclude /home/autrijus/hondah.par
PerlModule Apache::PAR
  • Prueba: 
    % GET http://localhost/myapp/cgi-perl/main.pl
Hon Dah!
  • Una aplicación web en un solo línea que funciona!

Recuperación de bibliotecas de forma on-demand

  • Con LWP instalado, puedes usar archivos PAR remotos: 
    use PAR;
use lib 'http://aut.dyndns.org/par/DBI-latest.par';
use DBI;    # siempre actualizado!
  • Los módulos ahora se mantienen en $ENV{PAR_GLOBAL_TEMP}
  • Actualizaciones automáticas con "LWP::Simple::mirror"
  • Descarga solo si ha sido modificada
  • Seguro para uso offline después de la primera vez
  • Puede usar "SIGNATURE" para prevenir spoofing DNS
•
Facilita la escalabilidad de implementación grande
  • Actualizaciones desde un lugar central
  • Sin necesidad de instaladores

Obfuscación de código

•
Además conocida como tecnologías de ocultación de fuentes
  • Es no criptografía
  • Ofrecida por PerlApp, Perl2Exe, Stunnix...
•
Normalmente fácil de desactivar
  • Tomar dump de optree en memoria, alimentar a "B::Deparse"
  • Si solo quieres detener a un casual "grep", "deflate" ya funciona
•
PAR ahora soporta filtros de entrada pluggables con "pp -f"
  • Prácticas incluidas: Bleach, PodStrip y PatchContent
  • True criptografía usando "Crypt::*"
  • o incluso _activación de producto_ en internet
•
Alternativamente, mantén el cálculo en tu servidor y usa RPC

Acceso a archivos comprimidos

  • Para obtener el archivo de host desde un programa comprimido: 
    my $zip = PAR::par_handle($0); # un objeto Archive::Zip
my $content = $zip->contents('MANIFEST');
  • Lo mismo, pero con read_file(): 
    my $content = PAR::read_file('MANIFEST');
  • Los archivos PAR cargados se almacenan en %PAR::LibCache: 
    use PAR '/home/mylibs/*.par';
while (my ($filename, $zip) = each %PAR::LibCache) {
    print "[$filename - MANIFEST]\n";
    print $zip->contents('MANIFEST');
}

Empaquetar aplicaciones GUI

  • Las bibliotecas de GUI a menudo necesitan vincularse con bibliotecas compartidas: 
    # busca libncurses en rutas de bibliotecas y empaqueta
% pp -l ncurses curses_app.pl  # mismo para Tk, Wx, Gtk, Qt...
  • Usa "pp --gui" en Win32 para eliminar la ventana de consola: 
    # empaqueta 'src.pl' en un 'out.exe' sin ventana de consola (solo Win32)
% pp --gui -o out.exe src.pl
  • "No puede localizar"

Distribuciones CPAN precompiladas

•
Instalar extensiones XS de CPAN solía ser difícil
  • Algunas plataformas no vienen con un compilador (Win32, MacOSX...)
  • Algunas cabeceras o bibliotecas pueden estar ausentes
  • PAR.pm en sí sufría ambos problemas
  • ...pero ya no. "Module::Install" al rescate!

use inc::Module::Install;      # era "use ExtUtils::MakeMaker;"

  • Claro, todavía tienes que escribir "make par" y subir el paquete precompilado
  • Los usuarios pueden instalarlo directamente con "parl -i"

Resumen de la Implementación de PAR.pm

•
Aquí empieza la parte horrible
  • Aparecen monstruos, dragones y jabberwocks...
  • Estás a punto de aprender cosas extrañas sobre el funcionamiento interno de Perl
•
PAR invoca cuatro áreas de la magia negra de Perl:
  • Referencias de código en @INC
  • Filtrado de fuentes en tiempo real
  • Reemplazo de DynaLoader::bootstrap() para módulos XS
  • Generación de ejecutables auto-arrancables
•
Los dos primeros solo funcionan en 5.6 o posterior
  • DynaLoader y %INC han estado presentes desde que nació Perl 5
  • PAR necesita 5.6, pero existe un port para 5.005

Referencias de código en @INC

•
El 19/07/1999, Ken Fox envió un parche a P5P
  • Para _permitir el uso de módulos remotos_ insertando un hook en @INC
  • Se aceptó para Perl 5.6, pero no se documentó hasta 5.8
  • Usa "perldoc -f require" para leer detalles
  • Los coderefs en @INC pueden devolver un fh, o undef para 'pasar': 
    push @INC, sub {
    my ($coderef, $filename) = @_;  # $coderef es \&my_sub
    open my $fh, "-|", "wget ftp://example.com/$filename";
    return $fh;        # ¡usando módulos remotos, sí!
};
  • Perl 5.8 permite abrir un handle de archivo a una cadena, así que solo usamos eso: 
    open my $fh, "<", \($zip->memberNamed($filename)->contents);
return $fh;
  • pero Perl 5.6 no tiene eso, y no quiero usar archivos temporales...

Filtrado de fuentes sin módulos Filter::*

•
... ¡características no documentadas al rescate!
  • Se descubrió que @INC puede devolver dos valores
  • El primero sigue siendo el handle del archivo
  • El segundo es un coderef para filtrado línea por línea
•
Así es como funciona "Acme::use::strict::with::pride": 
# Forzar que todos los módulos usados utilicen strict y warnings
open my $fh, "<", $filename or return;
my @lines = ("use strict; use warnings;\n", "#line 1 \"$full\"\n");
return ($fh, sub {
    return 0 unless @lines;    
    push @lines, $_; $_ = shift @lines; return length $_;
});

Filtrado de fuentes sin módulos Filter::* (cont.)

  • No tenemos un handle para nada
  • ¡Una característica no documentada salva el día!
  • Podemos omitir el primer valor de retorno por completo: 
    # Devolver todo el contenido línea por línea desde el archivo dentro de PAR
my @lines = split(
    /(?<=\n)/,
    $zip->memberNamed($filename)->contents
);
return (sub {
    $_ = shift(@lines);
    return length $_;
});

Sobrescribiendo DynaLoader::bootstrap

•
Los módulos XS tienen bibliotecas cargadas dinámicamente
  • No se pueden cargar como parte de un zip, así que las extraemos
  • Deben interceptar el proceso de búsqueda de bibliotecas de DynaLoader
•
Los nombres de los módulos se pasan a "bootstrap" para la carga de XS
  • Durante el proceso, llama a "dl_findfile" para localizar el archivo
  • Así que instalamos pre-hooks alrededor de ambas funciones
•
Nuestra "_bootstrap" simplemente comprueba si la biblioteca está en PARs
•
Si es así, la extrae a un archivo temporal usando "File::Temp"
•
El archivo se limpiará automáticamente cuando el programa termine
  • Luego pasa los argumentos a la "bootstrap" original
  • Finalmente, nuestra "dl_findfile" intercepta nombres conocidos y devuelve el archivo

Anatomía de un ejecutable PAR autocontenido

•
El script par ($0) en sí
•
Puede estar en texto plano o en formato ejecutable nativo
•
Cualquier número de archivos embebidos
  • Usado para arrancar las diversas dependencias de PAR
  • Cada sección comienza con la cadena mágica "FILE"
  • Longitud del nombre en pack('N') y el nombre (auto/.../)
  • Longitud en pack('N') y contenido del archivo (sin comprimir)
•
Un archivo PAR
•
Un archivo ZIP estándar con la cadena mágica "PK\003\004"
•
Sección final
  • Número pack('N') de la longitud total de FILE y PAR
  • Finalmente, debe haber una cadena mágica de 8 bytes: "\012PAR.pm\012"
