NOMBRE

PadWalker - juega con las variables léxicas de otros

SINOPSIS

use PadWalker qw(peek_my peek_our peek_sub closed_over);
...

DESCRIPCIÓN

PadWalker es un módulo que te permite inspeccionar (e incluso cambiar) las variables léxicas en cualquier subrutina que te haya llamado. Solo mostrará aquellas variables que estén en el ámbito en el momento de la llamada.

PadWalker es particularmente útil para la depuración. Incluso es utilizado por el depurador incorporado de Perl. (También se puede usar para el mal, por supuesto).

No recomendaría usar PadWalker directamente en código de producción, pero tú decides. Algunos de los módulos que utilizan PadWalker internamente son ciertamente seguros y útiles en producción.

peek_my NIVEL
peek_our NIVEL
El argumento NIVEL se interpreta igual que el argumento de "caller". Así, peek_my(0) devuelve una referencia a un hash de todas las variables "my" que están actualmente en ámbito; peek_my(1) devuelve una referencia a un hash de todas las variables "my" que están en ámbito en el punto donde se llamó a la subrutina actual, y así sucesivamente.

"peek_our" funciona de la misma manera, excepto que enumera las variables "our" en lugar de las variables "my".

El hash asocia cada nombre de variable con una referencia a su valor. Los nombres de las variables incluyen el sigilo, por lo que la variable $x se representa con la cadena '$x'.

Por ejemplo:

my $x = 12;
my $h = peek_my (0);
${$h->{'$x'}}++;
print $x;  # imprime 13

O un ejemplo más complejo:

sub increment_my_x {
  my $h = peek_my (1);
  ${$h->{'$x'}}++;
}
my $x=5;
increment_my_x;
print $x;  # imprime 6
peek_sub SUB
La rutina "peek_sub" toma una coderef como argumento y devuelve un hash de las variables "my" utilizadas en esa sub. Los valores generalmente serán indefinidos a menos que la sub esté en uso (es decir, en la cadena de llamadas) en ese momento. Por otro lado: 
my $x = "¡Hola!";
my $r = peek_sub(sub {$x})->{'$x'};
print "$$r\n";        # imprime '¡Hola!'

Si la sub define varias variables "my" con el mismo nombre, obtendrás la última. No conozco ningún uso para "peek_sub" que no se vea afectado negativamente por esto, y probablemente será obsoleto en una versión futura en favor de alguna interfaz alternativa.

closed_over SUB
"closed_over" es similar a "peek_sub", excepto que solo enumera las variables "my" que se utilizan en la subrutina pero se definen externamente: en otras palabras, las variables que se cierran sobre ellas. Esto *sí* tiene usos razonables: véase Data::Dump::Streamer, por ejemplo (una versión futura de la cual puede de hecho usar "closed_over").
set_closed_over SUB, HASH_REF
"set_closed_over" reasigna las variables de pad sobre las que se cierran las variables de la subrutina.

El segundo argumento es una referencia a un hash, muy similar a la devuelta por "closed_over".

var_name NIVEL, REF_VAR
var_name SUB, REF_VAR
"var_name(sub, var_ref)" devuelve el nombre de la variable referida por "var_ref", siempre que sea una variable "my" utilizada en la sub. El parámetro "sub" puede ser una referencia CODE o un número. Si es un número, se trata de la misma manera que el argumento de "peek_my".

Por ejemplo,

my $foo;
print var_name(0, \$foo);    # imprime '$foo'

sub my_name {
  return var_name(1, shift);
}
print my_name(\$foo);        # lo mismo
