PAR__Packer__Troubleshooting(3pm)

Paquete: perl-par-packer

Licencias: GPL

NOMBRE Documentación de Perl contribuida por usuarios PAR::Packer::SoluciónDeProblemas(3)

NOMBRE

PAR::Packer::SoluciónDeProblemas - Problemas comunes en la compresión de scripts con pp

SINTAXIS

Explicar algunos problemas comunes y soluciones cuando se comparten scripts con pp.

DESCRIPCIÓN

Módulos_faltantes

Cuando se ejecuta el ejecutable generado, se aborta con un mensaje similar a:

Can't locate Foo/Bar.pm in @INC (puede que necesite instalar el módulo Foo::Bar) 
  (@INC contiene: ...) en script/pp5yBDq.pl línea 1.
BEGIN fallido - compilación abortada en script/pp5yBDq.pl línea 1.

Tu script "require" el módulo "Foo::Bar" (probablemente indirectamente desde otro módulo), pero pp no lo ha incluido en el ejecutable. pp usa Module::ScanDeps para recurrir a tu script para encontrar los módulos "require" que se necesitan. A veces, esta búsqueda puede ser incompleta debido a las muchas formas en que Perl permite expresar su deseo de cargar un módulo.

Intenta compilar con opciones --compile o --execute para resolver el problema. Si falla, añade explícitamente el módulo con la opción -M, es decir:

% pp -M Foo::Bar ...

Puede haber que repetir la añadida de módulos, las variantes de -M con * pueden ser útiles aquí.

DLLs_nativas_faltantes

El ejecutable generado funciona bien en la máquina donde fue generado, pero se aborta con un mensaje similar al siguiente cuando se lo ejecuta en otra máquina (que puede no tener Perl instalado).

Can't load 'C:\Users\myuser\AppData\Local\Temp\3\par-74686f6b65\temp-1772\inc\lib/auto/Net/SSLeay/SSLeay.dll' para el módulo Net::SSLeay:
  load_file: El módulo especificado no pudo encontrarse en <embedded>/DynaLoader.pm línea 206. en <embedded>/PAR/Heavy.pm línea 95.

Aquí, la parte del módulo XS (Net::SSLeay) (.../auto/Net/SSLeay/SSLeay.dll) que tiene la parte DLL (lib/ssl*.dll) ha sido compresada, pero está vinculada a una DLL nativa que no ha sido compresada. La DLL nativa está claramente presente en la máquina donde se compresó, pero no en la otra máquina. Nota que pp (o bien Module::ScanDeps) no detecta tal dependencia no-Perl y por lo tanto no comprimirá la DLL nativa, tendrías que agregarla manualmente (usando opción --link).

TL;DR Usa pp_autolink de "App::PP::Autolink" para automatizar la compresión de DLLs nativas y terminar con ello, o lee más sobre los detalles gorriones.

Inspecciona .../auto/Net/SSLeay/SSLeay.dll (usando herramientas como objdump) muestra que está vinculada a DLLs nativas libssl*.dll y libcrypto*.dll. Estas DLLs vienen de OpenSSL. Nota los * en los nombres anteriores, son versiones. Una vez que tengas los nombres exactos, puedes añadir estos DLLs a la línea de comandos de pp con "--link ...". Pero no está hecho: libcrypto*.dll está generalmente vinculada a libz*.dll, así que tienes que añadir "--link ..." de ese. Nota que este ejemplo usa el sufijo Windows ".dll", pero el problema también existe en Linux o macOS.

"Intentar_reemplazar..._abortado._Compilación_fallida_en_require..."

Hay varios escenarios donde "Intentar_reemplazar..._abortado._Compilación_fallida_en_require..." puede ser emitido: es solo un indicador de que una anterior "require" de algo falló, pero el error fue suprimido y luego algo fue "require" de nuevo. La razón original del error estaría indicada, pero no lo es.

Aquí es un ejemplo, foo.pl.

use strict;
use warnings;
use feature qw( say state );
eval {
    say "primero Foo";
    require Foo;
};
#say "requerir fallido: $@" si $@;   # <---
say "Text::ParseWords ...";
require Text::ParseWords;
say "segundo Foo";
require Foo;

Ahora ejecuta:

% echo "use Bar; 1;" > Foo.pm
% echo "use Quux; 1;" > Bar.pm
% perl -I. foo.pl
primero Foo
Text::ParseWords ...
segundo Foo
Intentar_reemplazar Foo.pm abortado.
Compilación fallida en require en foo.pl línea 28.

Descomenta la línea con el puntero para ver la razón real: "No se puede encontrar Quux.pm en @INC ... en Bar.pm línea 1.", es decir, Quux.pm no está presente. Nota que el mensaje original no menciona "Quux.pm".

Ahora intenta esto:

% echo "{" > Quux.pm        # sí, es un error sintáctico
% perl -I. foo.pl 
primero Foo
Text::ParseWords ...
segundo Foo
Intentar_reemplazar Foo.pm abortado.
Compilación fallida en require en foo.pl línea 28.

Resultado similar al anterior. De nuevo, descomenta la línea con el puntero para ver la razón real: "Falta corchete o llave rectangular en Quux.pm línea 1 ... error sintáctico en Quux.pm línea 1, al final.". Por lo tanto, Quux.pm existe, pero no se puede cargar debido a un error de sintaxis. Hay otras razones por las que un módulo podría no cargarse, por ejemplo "DLLs_nativas_faltantes".

Aquí está una receta para reducir el problema. Agrega lo siguiente antes de la primera instrucción Perl de foo.pl:

BEGIN {
    my $required;
    unshift @INC, sub {
        (undef, $required) = @_;
        my (undef, $filename, $line) = caller();
        print STDERR "requerir $required desde ${filename}:${line}\n";
        return;
    };
    push @INC, sub { print STDERR "FALTANTE $required\n"; return; };
}

Este registra cualquier intento de "require" de algo incluyendo el sitio de llamada. No puede registrar si la "require" fue exitosa o el error en caso de falla. Pero si la falla es solo un módulo faltante, imprimirá "FALTANTE algo".

Ahora intenta los dos variantes de nuevo. Aquí está el caso de "FALTANTE algo" (muestra solo "stderr"):

requerir strict.pm de foo.pl:14
requerir warnings.pm de foo.pl:15
requerir feature.pm de foo.pl:16
requerir Foo.pm de foo.pl:22
requerir Bar.pm de Foo.pm:1
requerir Quux.pm de Bar.pm:1
FALTANTE Quux.pm
requerir Text/ParseWords.pm de foo.pl:27
requerir Exporter.pm de /usr/lib/x86_64-linux-gnu/perl-base/Text/ParseWords.pm:8
Intentar_reemplazar Foo.pm abortado.
Compilación fallida en require en foo.pl línea 28.

y el caso de "no cargar":

requerir strict.pm de foo.pl:14
requerir warnings.pm de foo.pl:15
requerir feature.pm de foo.pl:16
requerir Foo.pm de foo.pl:22
requerir Bar.pm de Foo.pm:1
requerir Quux.pm de Bar.pm:1
requerir Text/ParseWords.pm de foo.pl:27
requerir Exporter.pm de /usr/lib/x86_64-linux-gnu/perl-base/Text/ParseWords.pm:8
Intentar_reemplazar Foo.pm abortado.
Compilación fallida en require en foo.pl línea 28.

La estrategia para encontrar la causa de "Intentar_reemplazar algo" es:

  • Encuentra la primera ocurrencia de "requerir algo" en la salida.
  • Avanza por la cadena de llamadas de "require" anidadas, manteniéndote "debajo" de algo. El culpable es generalmente el último módulo mencionado en una línea de "requerir ... desde ...".
  • Si la línea siguiente es "FALTANTE algo" entonces es un caso de "Módulos_faltantes" con algo como culpable. De lo contrario, es un error de carga, probablemente "DLLs_nativas_faltantes".

En el ejemplo anterior, la cadena de llamadas es:

foo.pl -> Foo.pm -> Bar.pm -> Quux.pm

(Text/ParseWords.pm es "require" de foo.pl, por lo que "arriba" es Foo.pm). Esto implicaría Quux.pm. Nota que la cadena de llamadas no tiene que ser regular, eso es solo el caso si todas las "require" vienen de "use" que se ejecutan en tiempo de compilación. La imagen podría estar desviada si se usan "require" en tiempo de ejecución.
