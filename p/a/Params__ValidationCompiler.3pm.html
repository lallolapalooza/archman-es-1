Params::ValidationCompiler(3) Documentación Perl contribuida por el usuario Params::ValidationCompiler(3)

NOMBRE

Params::ValidationCompiler - Compila un validador de parámetros de subrutina optimizado una vez, úsalo para siempre

VERSIÓN

versión 0.31

SINOPSIS

use Types::Standard qw( Int Str );
use Params::ValidationCompiler qw( validation_for );
{
    my $validator = validation_for(
        params => {
            foo => { type => Int },
            bar => {
                type     => Str,
                optional => 1,
            },
            baz => {
                type    => Int,
                default => 42,
            },
        },
    );
    sub foo {
        my %args = $validator->(@_);
    }
}
{
    my $validator = validation_for(
        params => [
            { type => Int },
            {
                type     => Str,
                optional => 1,
            },
        ],
    );
    sub bar {
        my ( $int, $str ) = $validator->(@_);
    }
}
{
    my $validator = validation_for(
        params => [
            foo => { type => Int },
            bar => {
                type     => Str,
                optional => 1,
            },
        ],
        named_to_list => 1,
    );
    sub baz {
        my ( $foo, $bar ) = $validator->(@_);
    }
}

DESCRIPCIÓN

Este módulo crea una subrutina personalizada y altamente eficiente para la verificación de parámetros. Puede manejar parámetros con nombre o posicionales, y puede devolver los parámetros como pares clave/valor o como una lista de valores.

Además de las comprobaciones de tipo, también admite valores predeterminados para parámetros, parámetros opcionales y parámetros adicionales "slurpy" (que absorben el resto).

PARÁMETROS

Este módulo tiene dos opciones exportadas, "validation_for" y "source_for". Ambas subrutinas aceptan las mismas opciones:

params

Un arrayref o hashref que contiene una especificación de parámetros.

Si pasas un hashref, la subrutina validadora generada esperará parámetros con nombre. El valor de "params" debe ser un hashref donde los nombres de los parámetros sean las claves y las especificaciones sean los valores.

Si pasas un arrayref y "named_to_list" es falso, el validador esperará parámetros posicionales. Cada elemento del arrayref "params" debe ser una especificación de parámetro.

Si pasas un arrayref y "named_to_list" es verdadero, el validador esperará parámetros con nombre, pero devolverá una lista de valores. En este caso, el arrayref debe contener una *lista* de pares clave/valor, donde los nombres de los parámetros son las claves y las especificaciones son los valores.

Cada especificación puede contener un booleano o un hashref. Si la especificación es un booleano, indica requerido (verdadero) u opcional (falso).

La especificación hashref acepta las siguientes claves:

  • type

    Un objeto de tipo. Puede ser un tipo Moose (de Moose o MooseX::Types), un tipo Type::Tiny o un tipo Specio.

    Si el tipo tiene coerciones, estas siempre se utilizarán.

  • default

    Puede ser un escalar simple (sin referencia) o una referencia a una subrutina. La referencia a la subrutina se llamará sin argumentos (por ahora).

  • optional

    Un booleano que indica si el parámetro es opcional o no. Por defecto, los parámetros son requeridos a menos que proporciones un valor predeterminado.

slurpy

Si este es un valor simple verdadero, la subrutina generada acepta argumentos adicionales no especificados en "params". Por defecto, los argumentos extra causan una excepción.

También puedes pasar una restricción de tipo aquí, en cuyo caso todos los argumentos extra deben ser valores del tipo especificado.

named_to_list

Si esto es verdadero, la subrutina generada esperará una lista de pares clave/valor o un hashref y devolverá una lista que contenga solo valores. Los "params" que pases deben ser un arrayref de pares clave/valor. El orden de estos pares determina el orden en el que se devuelven los valores.

No puedes combinar "slurpy" con "named_to_list", ya que no hay forma de saber cómo ordenar los valores de retorno adicionales.

return_object

Si esto es verdadero, la subrutina generada devolverá un objeto en lugar de un hashref. No puedes establecer esta opción a verdadero si has establecido "slurpy" o "named_to_list".

Los métodos del objeto corresponden a los nombres de los parámetros pasados a la subrutina. Si bien llamar a métodos en un objeto es más lento que acceder a un hashref, la ventaja es que si cometes un error tipográfico en un nombre de parámetro, obtendrás un error útil.

Si tienes Class::XSAccessor instalado, se usará para crear los métodos de la clase, lo que lo hace bastante rápido.

El objeto devuelto se encuentra en una clase generada. No confíes en que el nombre de esta clase sea algo específico, y no verifiques este objeto usando "isa", "DOES" o algo similar.

Cuando "return_object" es verdadero, la especificación del parámetro hashref también acepta las siguientes claves adicionales:

  • getter

    Úsalo para establecer un nombre de método getter explícito para el parámetro. Por defecto, el nombre del método será el mismo que el nombre del parámetro. Ten en cuenta que si el nombre del parámetro no es un subnombre válido, obtendrás un error al compilar la subrutina de validación a menos que especifiques un getter para el parámetro.

  • predicate

    Úsalo para solicitar la creación de un método predicado para este parámetro. El método predicado devuelve verdadero si se pasó el parámetro y falso si no. Ten en cuenta que esto solo es útil para parámetros opcionales, pero puedes solicitar un predicado para cualquier parámetro.

EXPORTACIONES

Las subs exportadas son:

validation_for(...)

Devuelve una subrutina que implementa la verificación de parámetros específica. Esta subrutina espera recibir los parámetros a validar en @_. Si todos los parámetros son válidos, devolverá los parámetros validados (con valores predeterminados según corresponda), ya sea como una lista de pares clave/valor o como una lista de solo valores. Si alguno de los parámetros no es válido, lanzará una excepción.

Para validadores que esperan parámetros con nombre, la subrutina generada acepta una lista de pares clave/valor o un único hashref. De lo contrario, el validador espera una lista de valores.

Por ahora, debes extraer tú mismo el invocante.

Esta subrutina acepta los siguientes parámetros adicionales:

  • name

    Si se proporciona, la subrutina generada se nombrará utilizando Sub::Util. Esto es muy recomendable, ya que hace posible distinguir diferentes subrutinas de verificación al perfilar o en rastreos de pila.

    Este nombre también se utilizará en algunos mensajes de excepción, incluso si Sub::Util no está disponible.

    Ten en cuenta que debes instalar Sub::Util por separado, ya que no es un requisito de esta distribución, para evitar requerir un compilador.

  • name_is_optional

    Si esto es verdadero, el nombre se ignora cuando "Sub::Util" no está instalado. Si esto es falso, pasar un nombre cuando Sub::Util no puede ser cargado causa una excepción.

    Esto es útil para módulos CPAN donde quieres establecer un nombre si puedes, pero no quieres añadir un requisito previo en Sub::Util.

  • debug

    Establece la variable de entorno "EVAL_CLOSURE_PRINT_SOURCE" a verdadero antes de llamar a Eval::Clos

NAME

Params::ValidationCompiler - Compile parameter validation subroutines

VERSION

This module is part of the Params-ValidationCompiler distribution that was released in version 0.31.

SYNOPSIS

  use Params::ValidationCompiler qw( compiler );

  my $compiler = compiler(
      {
          name => {
              isa => 'Str',
              required => 1,
          },
          password => {
              isa => 'Str',
              required => 1,
          },
          email => {
              isa => 'Email',
          },
      }
  );

  # The following would fail (and raise an exception)
  # $compiler->(
  #     name => 'Test User',
  #     password => 'testing',
  # );

  # The following would succeed
  my $result = $compiler->(
      name => 'Test User',
      password => 'testing',
      email => 'test@example.com',
  );

  # $result is now a hashref
  # {
  #     name => 'Test User',
  #     password => 'testing',
  #     email => 'test@example.com',
  # }

  # You can also supply a subroutine for a custom validation
  my $compiler_with_custom = compiler(
      {
          foo => {
              isa => 'Int',
              callbacks => [ sub { my ($value) = @_; return $_ > 5 }, ],
          },
      }
  );

  $compiler_with_custom->(foo => 10); # Succeeds

  # $compiler_with_custom->(foo => 3); # Fails

DESCRIPTION

This module is designed to compile parameter validation routines. You pass it a hash reference describing the parameters that you expect to receive, and it will return a subroutine that you can then use to validate your parameters.

The subroutine returned by compiler will expect parameters in the same way that Moose does, i.e. as a hash reference.

The validation subroutine will die with a helpful error message if the parameters are invalid. If the parameters are valid, it will return a hash reference containing the validated parameters. This hash reference is a deep copy of the input, so modifications to the returned hash will not affect the original.

This module is based on the system used by MooseX::Params::Validate. However, it has been rewritten from scratch to be more efficient and to provide a cleaner API.

The primary goal of this module is to be fast. The validation subroutines are generated at compile time, and are therefore as fast as possible at runtime.

Types

The following types are supported out of the box:

  • Str: Checks that the value is a string.
  • Int: Checks that the value is an integer.
  • Num: Checks that the value is a number.
  • Bool: Checks that the value is a boolean.
  • ArrayRef: Checks that the value is an array reference.
  • HashRef: Checks that the value is a hash reference.
  • CodeRef: Checks that the value is a code reference.
  • RegexpRef: Checks that the value is a regular expression reference.
  • Maybe: Allows the value to be undef. Maybe[Str] means it can be undef or a string.
  • Email: Checks that the value looks like an email address.
  • Object: Checks that the value is an object. Object[SomeClass] checks that the value is an object of class SomeClass or a subclass thereof.
  • Const: Checks that the value is one of a set of allowed constants. See the example below.

You can also use Moose types. Just use the fully qualified name of the type.

  my $compiler = compiler({
      foo => { isa => 'Moose::Meta::TypeConstraint::Integer' },
  });

You can also use the shortcut form: isa => 'Moose::Meta::TypeConstraint::Integer'

You can also specify a custom type, which must be a subroutine that takes a single argument (the value) and returns true if the value is valid, or false otherwise.

  my $compiler = compiler({
      foo => {
          isa => sub { my ($value) = @_; return $value =~ /\A\d+\Z/ },
      },
  });

Options

Each parameter can have the following options:

isa

Required. The type of the parameter. See the Types section above.

required

Boolean. If true, the parameter is required. Defaults to false.

default

The default value for the parameter. This will only be used if the parameter is not provided. If the parameter is provided, its value will be used, even if it is undef.

weak_default

Boolean. If true, the default value will be used even if the parameter is provided but undef. Defaults to false.

callbacks

An array reference of subroutines. Each subroutine will be called with the value of the parameter. If any subroutine returns false, the validation fails.

clearer

Boolean. If true, a clearer subroutine will be generated for this parameter. The clearer will be named clear_param_name.

reader

Boolean. If true, a reader subroutine will be generated for this parameter. The reader will be named param_name.

writer

Boolean. If true, a writer subroutine will be generated for this parameter. The writer will be named set_param_name.

init_arg

The name of the argument to use when initializing the parameter. Defaults to the parameter name.

handles_undef

Boolean. If true, the parameter validator will not die if the value is undef. This is useful for parameters that are optional. Defaults to false.

Const Type

The Const type allows you to specify a set of allowed values for a parameter.

  my $compiler = compiler({
      status => {
          isa => Const[qw( pending complete failed )],
          required => 1,
      },
  });

  $compiler->(status => 'complete'); # Succeeds
  # $compiler->(status => 'invalid'); # Fails

Object Type

The Object type allows you to specify that a parameter must be an instance of a particular class.

  my $compiler = compiler({
      user => { isa => Object['My::User'] },
  });

  # $compiler->(user => My::User->new); # Succeeds
  # $compiler->(user => 'a string'); # Fails

Maybe Type

The Maybe type allows you to specify that a parameter can be undef.

  my $compiler = compiler({
      description => { isa => Maybe[Str] },
  });

  $compiler->(description => 'This is a description.'); # Succeeds
  $compiler->(description => undef); # Succeeds
  # $compiler->(description => 123); # Fails

Nested Parameters

You can also validate nested hash references.

  my $compiler = compiler({
      user => {
          isa => HashRef,
          required => 1,
          fields => {
              name => { isa => 'Str', required => 1 },
              age  => { isa => 'Int' },
          },
      },
  });

  $compiler->(
      user => {
          name => 'Test User',
          age => 30,
      },
  ); # Succeeds

  # $compiler->(
  #     user => {
  #         name => 'Test User',
  #     },
  # ); # Fails (age is missing)

Callbacks and Default Values

Callbacks are executed after the type check, but before any default values are applied.

  my $compiler = compiler({
      foo => {
          isa => 'Int',
          callbacks => [sub { $_[0] > 5 }],
          default => 10,
      },
  });

  # $compiler->(foo => 3); # Fails (callback)
  $compiler->(foo => 6); # Succeeds, returns { foo => 6 }
  $compiler->({}); # Succeeds, returns { foo => 10 }

Subroutine Generation

This module uses Eval::Closure to generate the subroutines. This allows the subroutines to be compiled at compile time, making them very fast at runtime.

If you want to see the generated source code, you can set the environment variable PERL_PARAMS_VALIDATIONCOMPILER_DEBUG to a true value.

This will cause Eval::Closure::eval_closure() to be called with the keep_code option set to true. This causes the source of the subroutine to be printed before it's "eval"'d.

source_for(...)

This returns a two element list. The first is a string containing the source code for the generated sub. The second is a hashref of "environment" variables to be used when generating the subroutine. These are the arguments that are passed to Eval::Closure.
