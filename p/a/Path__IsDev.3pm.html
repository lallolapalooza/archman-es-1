Path__IsDev(3pm)

Path::IsDev(3pm) Documentación Perl Contribuida por Usuarios Path::IsDev(3pm)

NOMBRE

Path::IsDev - Determinar si una ruta dada se asemeja a un árbol de fuente de desarrollo

VERSIÓN

versión 1.001003

SINOPSIS

use Path::IsDev qw(is_dev);
if( is_dev('/alguna/ruta') ) {
    ...
} else {
    ...
}

DESCRIPCIÓN

Este módulo es, más o menos, un conjunto de heurísticas para determinar si una ruta dada es la raíz de un árbol de desarrollo de algún tipo.

Esto tiene muchas aplicaciones útiles, notablemente aquellas que requieren que los comportamientos para los módulos "instalados" sean diferentes a los que todavía están "en desarrollo"

FUNCIONES

debug

Callback de depuración.

Para habilitar la depuración:

export PATH_ISDEV_DEBUG=1

"is_dev"

Usando un "is_dev" "importado":

if( is_dev( $path ) ) {
}

Aunque las heurísticas reales utilizadas se basarán en cómo se llamó a "import".

Adicionalmente, puedes llamar

Path::IsDev::is_dev

sin "importar" nada, y se comportará exactamente igual que si lo hubieras importado usando

use Path::IsDev qw( is_dev );

Es decir, ninguna especificación de "set" es aplicable, por lo que solo obtendrás el "predeterminado".

ENTENDER Y DEPURAR ESTE MÓDULO

Entender cómo funciona este módulo es crucial para comprender dónde puedes usarlo y las consecuencias de usarlo.

Este módulo opera a un nivel muy simplista, y es fácil que ocurran falsos positivos.

Hay dos tipos de Heurísticas, Heurísticas Positivas/Confirmadoras y Heurísticas Negativas/Disconfirmadoras.

Las Heurísticas Positivas y las Heurísticas Negativas se basan únicamente en la presencia de archivos marcadores específicos en un directorio, o directorios marcadores especiales.

Por ejemplo, los archivos "META.yml", "Makefile.PL", y "Build.PL" son todos marcadores de Heurística Positiva, porque su presencia a menudo indica una "raíz" de un árbol de desarrollo.

Y por ejemplo, los directorios "t/", "xt/" y ".git/" también son marcadores de Heurística Positiva, porque estas estructuras son comunes en los árboles de desarrollo de "perl", y poco comunes en los árboles de instalación.

Sin embargo, estos marcadores a veces fallan, por ejemplo, considera que tienes una instalación de "local::lib" o "perlbrew" en $HOME

$HOME/
$HOME/lib/
$HOME/perl5/perls/perl-5.19.3/lib/site_perl/

Etc.

En circunstancias normales, ni $HOME ni esas 3 rutas se consideran "dev".

Sin embargo, todo lo que se necesita para causar un falso positivo es que alguien instale un directorio "t" o "xt", o un archivo marcador en uno de los directorios anteriores para que path_isdev($dir) devuelva verdadero.

Esto puede no ser un problema, al menos, hasta que uses "Path::FindDev" que combina "Path::IsDev" con recorrido recursivo hacia arriba.

$HOME/
$HOME/lib/
$HOME/perl5/perls/perl-5.19.3/lib/site_perl/
find_dev('$HOME/perl5/perls/perl-5.19.3/lib/site_perl/') # devuelve falso, porque no está dentro de un directorio dev
mkdir $HOME/t
find_dev('$HOME/perl5/perls/perl-5.19.3/lib/site_perl/') # devuelve $HOME, porque $HOME/t existe.

Y es este tipo de problema el que suele pillar desprevenido a la gente.

    HEURÍSTICAS

    Este módulo utiliza un sistema de "heurísticas" para determinar si un directorio es probable que sea un directorio de desarrollo.

    •
    El directorio padre contiene un archivo "Build.PL".
    •
    "VCS::Git" - Un directorio ".git".

    CONJUNTOS DE HEURÍSTICAS

    Conjuntos de heurísticas incluidos en esta distribución

    •
    "Básico" - El conjunto básico de heurísticas que contiene la mayoría, si no todas, las heurísticas.

    USO AVANZADO

    Conjuntos personalizados

    "Path::IsDev" tiene un sistema de "conjuntos" de Heurísticas, para permitir tipos de heurísticas flexibles y conectables.

    Aunque, para la gran mayoría de los casos, esto no es necesario.

    use Path::IsDev is_dev => { set => 'Basic' };
use Path::IsDev is_dev => { set => 'SomeOtherSet' , -as => 'is_dev_other' };

    Anulación del conjunto predeterminado

    Si por alguna razón el conjunto "Básico" es insuficiente, o si genera falsos positivos en su sistema por alguna razón, el conjunto "predeterminado" puede ser anulado.

    export PATH_ISDEV_DEFAULT_SET="SomeOtherSet"
...
use Path::IsDev qw( is_dev );
is_dev('/some/path') # usa SomeOtherSet

    Sin embargo, esto solo tendrá prioridad en el caso de que el conjunto no se especifique durante la "importación".

    Si esto representa una preocupación de seguridad para el usuario, entonces este agujero de seguridad puede eliminarse declarando el conjunto que desea en el código:

    export PATH_ISDEV_DEFAULT_SET="SomeOtherSet"
...
use Path::IsDev  is_dev => { set => 'Basic' };
is_dev('/some/path') # usa Basic, independientemente de ENV

    SEGURIDAD

    Es concebible que un usuario malintencionado pueda construir un conjunto malicioso, que contenga código arbitrario y vulnerable, y posiblemente ocultar ese conjunto malicioso en el @INC de un usuario privilegiado mal asegurado.

    Y si lograran lograr eso, si pudieran envenenar el %ENV del usuario privilegiado, podrían engañar al usuario privilegiado para que ejecute código arbitrario.

    Aunque, seamos sinceros, si puedes hacer cualquiera de esas 2 cosas, probablemente ya eres vulnerable a la seguridad, y seamos sinceros, si pudieras hacer cualquiera de esas 2 cosas podrías hacer cosas mucho más maliciosas por lo siguiente:

    export PERL5OPT="-MEvil::Module"

    Así que, entendiendo eso, decir que la utilidad predeterminada de este módulo es "insegura" es en gran medida un argumento falso.

    Y a tal efecto, este módulo no hace nada para "bloquear" ese mecanismo, y este módulo le anima a **NO** forzar un conjunto, a menos que **LO NECESITE**, y sugiere encarecidamente que forzar un conjunto con el propósito de seguridad no logrará ninguna mejora real en la seguridad, al mismo tiempo que reduce la utilidad.
