Paquete: perl-path-tiny

Path::Tiny(3) Documentación de Perl contribuida por el usuario Path::Tiny(3) 

$path = path("foo/bar");
$path = path("/tmp", "file.txt"); # lista
$path = path(".");                # cwd

Construye un objeto "Path::Tiny". No importa si le das una ruta de archivo o directorio. Sigue siendo tu responsabilidad llamar a métodos de tipo directorio solo en directorios y métodos de tipo archivo solo en archivos. Esta función se exporta automáticamente por defecto.

El primer argumento debe estar definido y tener una longitud distinta de cero o se lanzará una excepción. Esto evita errores sutiles y peligrosos con código como "path( maybe_undef() )->remove_tree".

OBSOLETO: Si y solo si el **primer** carácter del **primer** argumento de "path" es una tilde ('~'), entonces se aplicará el reemplazo de tilde al primer segmento de ruta. Una tilde única se reemplazará con glob('~') y una tilde seguida de un nombre de usuario se reemplazará con la salida de glob('~username'). **Ningún otro método realiza expansión de tildes en sus argumentos**. Consulte "Expansión de tildes (obsoleto)" para más información.

En Windows, si la ruta consiste en un identificador de unidad sin un componente de ruta ("C:" o "D:"), se expandirá a la ruta absoluta del directorio actual en ese volumen usando Cwd::getdcwd().

Si se llama con un único argumento de "Path::Tiny", se devuelve el original a menos que el original contenga una referencia a un archivo o directorio temporal, en cuyo caso se crea una copia en forma de cadena.

$path = path("foo/bar");
$temp = Path::Tiny->tempfile;
$p2 = path($path); # como $p2 = $path
$t2 = path($temp); # como $t2 = path( "$temp" )

Esto optimiza las copias sin proliferar referencias inesperadamente si una copia es realizada por código fuera de tu control.

API actual disponible desde 0.017.

$path = Path::Tiny->new("foo/bar");

Esto es igual que "path", pero con sobrecarga de llamada al método. (¿Por qué harías eso?)

API actual disponible desde 0.001.

$path = Path::Tiny->cwd; # path( Cwd::getcwd )
$path = cwd; # export opcional

Te da la ruta absoluta al directorio actual como un objeto "Path::Tiny". Esto es ligeramente más rápido que "path(".")->absolute".

"cwd" puede ser exportado a petición y utilizado como una función en lugar de como un método.

API actual disponible desde 0.018.

$path = Path::Tiny->rootdir; # /
$path = rootdir;             # export opcional

Te da "File::Spec->rootdir" como un objeto "Path::Tiny" si eres demasiado quisquilloso para path("/").

"rootdir" puede ser exportado a petición y utilizado como una función en lugar de como un método.

API actual disponible desde 0.018.

$temp = Path::Tiny->tempfile( @options );
$temp = Path::Tiny->tempdir( @options );
$temp = $dirpath->tempfile( @options );
$temp = $dirpath->tempdir( @options );
$temp = tempfile( @options ); # export opcional
$temp = tempdir( @options );  # export opcional

"tempfile" pasa las opciones a "File::Temp->new" y devuelve un objeto "Path::Tiny" con el nombre del archivo. La opción "TMPDIR" estará habilitada por defecto, pero puedes anularlo pasando "TMPDIR => 0" junto con las opciones. (Si usas una opción "TEMPLATE" absoluta, querrás deshabilitar "TMPDIR".)

El objeto "File::Temp" resultante se almacena en caché. Cuando el objeto "Path::Tiny" se destruye, el objeto "File::Temp" también lo hará.

"File::Temp" requiere molesta- mente que especifiques una plantilla personalizada de maneras ligeramente diferentes dependiendo de qué función o método llames, pero "Path::Tiny" te permite ignorar eso y puede aceptar una plantilla inicial o una opción de "TEMPLATE" y hace lo correcto.

$temp = Path::Tiny->tempfile( "customXXXXXXXX" );             # ok
$temp = Path::Tiny->tempfile( TEMPLATE => "customXXXXXXXX" ); # ok

El objeto de ruta de archivo temporal se normalizará para tener una ruta absoluta, incluso si se creó en un directorio relativo usando "DIR". Si quieres que tenga el "realpath" en su lugar, pasa un hash de opciones inicial como este:

$real_temp = tempfile({realpath => 1}, @options);

"tempdir" es igual que "tempfile", excepto que llama a "File::Temp->newdir" en su lugar.

Tanto "tempfile" como "tempdir" pueden ser exportados a petición y utilizados como funciones en lugar de como métodos.

Los métodos se pueden llamar en instancias que representan un directorio. En este caso, el directorio se utiliza como base para crear el archivo/directorio temporal, estableciendo la opción "DIR" en File::Temp.

my $target_dir = path('/to/destination');
my $tempfile = $target_dir->tempfile('foobarXXXXXX');
$tempfile->spew('A lot of data...');  # no atómico
$tempfile->move($target_dir->child('foobar')); # con suerte atómico

En este caso, cualquier valor establecido para la opción "DIR" se ignora.

Nota: para archivos temporales, los manejadores de archivo de File::Temp se cierran y no se reutilizan. Esto no es tan seguro como usar manejadores de File::Temp directamente, pero es menos propenso a interbloqueos o problemas de acceso en algunas plataformas. Piensa que lo que te da "Path::Tiny" es solo un **nombre** de archivo temporal que se limpiará.

Nota 2: si no quieres que se limpien automáticamente cuando el objeto se destruye, File::Temp requiere opciones diferentes para directorios y archivos. Usa "CLEANUP => 0" para directorios y "UNLINK => 0" para archivos.

Nota 3: No pierdas el objeto temporal encadenando una llamada a método en lugar de almacenarlo:

my $lost = tempdir()->child("foo"); # tempdir se limpia de inmediato

Nota 4: El objeto almacenado en caché se puede acceder con el método "cached_temp". Mantener una referencia, o modificar el objeto en caché, puede romper el comportamiento documentado anteriormente y no está soportado. Úsalo bajo tu propio riesgo.

API actual disponible desde 0.119.

$abs = path("foo/bar")->absolute;
$abs = path("foo/bar")->absolute("/tmp");

Devuelve un nuevo objeto "Path::Tiny" con una ruta absoluta (o él mismo si ya es absoluto). Si no se proporciona argumento, el directorio actual se utiliza como ruta base absoluta. Si se proporciona un argumento, se convertirá a una ruta absoluta (si aún no lo es) y se utilizará como ruta base absoluta.

Esto no resolverá directorios ascendentes ("foo/../bar") a menos que "canonpath" en File::Spec lo haga normalmente en tu plataforma. Si necesitas que se resuelvan, debes llamar al método más costoso "realpath" en su lugar.

En Windows, una ruta absoluta sin un componente de volumen tendrá uno añadido basado en la unidad actual.

API actual disponible desde 0.101.

path("foo.txt")->append(@data);
path("foo.txt")->append(\@data);
path("foo.txt")->append({binmode => ":raw"}, @data);
path("foo.txt")->append_raw(@data);
path("foo.txt")->append_utf8(@data);

Añade datos a un archivo. El archivo se bloquea con "flock" antes de escribir y se cierra después. Se puede utilizar una referencia a hash opcional para pasar opciones. Las opciones válidas son:

La opción "truncate" es una forma de reemplazar el contenido de un archivo **en el lugar**, a diferencia de "spew", que escribe en un archivo temporal y luego reemplaza el original (si existe).

"append_raw" es como "append" con un "binmode" de ":unix" para una escritura rápida, sin búfer y en bruto.

Este sitio no está asociado de ninguna forma con Arch Linux ni afiliado a este proyecto. El contenido es únicamente una traducción de las páginas del manual de Arch publicadas en man.archlinux.org.

"append_utf8" es como "append" con un "binmode" no almacenado en búfer :unix:encoding(UTF-8) (o ":unix:utf8_strict" con PerlIO::utf8_strict). Si Unicode::UTF8 0.58 o superior está instalado, se realizará una escritura no almacenada en búfer y en bruto en los datos codificados con "Unicode::UTF8".

API actual disponible desde 0.060.

$path = path("foo.txt")->assert( sub { $_->exists } );

Devuelve el invocante después de afirmar que una referencia de código dada devuelve verdadero. Cuando se ejecuta la referencia de código de afirmación, tendrá el objeto invocante en la variable $_. Si devuelve falso, se lanzará una excepción. La referencia de código de afirmación también puede lanzar su propia excepción.

Si no se proporciona ninguna afirmación, se devuelve el invocante sin error.

API actual disponible desde 0.062.

$name = path("foo/bar.txt")->basename;        # bar.txt
$name = path("foo.txt")->basename('.txt');    # foo
$name = path("foo.txt")->basename(qr/.txt/);  # foo
$name = path("foo.txt")->basename(@suffixes);

Devuelve la parte del archivo o la última parte del directorio de una ruta.

Dada una lista de sufijos como cadenas o expresiones regulares, cualquiera que coincida al final de la parte del archivo o de la última parte del directorio se eliminará antes de devolver el resultado.

API actual disponible desde 0.054.

$canonical = path("foo/bar")->canonpath; # foo\bar en Windows

Devuelve una cadena con el formato canónico del nombre de la ruta para la plataforma. En particular, esto significa que los separadores de directorio serán "\" en Windows.

API actual disponible desde 0.001.

Devuelve el objeto de "File::Temp" o "File::Temp::Dir" almacenado en caché si el objeto "Path::Tiny" se creó con "/tempfile" o "/tempdir". Si no existe tal objeto, este método lanza una excepción.

ADVERTENCIA: Mantener una referencia al objeto almacenado en caché o modificarlo puede romper el comportamiento documentado para archivos y directorios temporales creados con "Path::Tiny" y no es compatible. Úselo bajo su propio riesgo.

API actual disponible desde 0.101.

$file = path("/tmp")->child("foo.txt"); # "/tmp/foo.txt"
$file = path("/tmp")->child(@parts);

Devuelve un nuevo objeto "Path::Tiny" relativo al original. Funciona como "catfile" o "catdir" de File::Spec, pero sin importar si es un archivo o un directorio.

ADVERTENCIA: dado que el argumento podría contener ".." o referirse a enlaces simbólicos, no hay garantía de que la nueva ruta se refiera a un descendiente real del original. Si esto es importante para usted, transforme el padre y el hijo con "realpath" y compruebe con "subsumes".

API actual disponible desde 0.001.

@paths = path("/tmp")->children;
@paths = path("/tmp")->children( qr/\.txt\z/ );

Devuelve una lista de objetos "Path::Tiny" para todos los archivos y directorios dentro de un directorio. Excluye "." y ".." automáticamente.

Si se proporciona un argumento opcional "qr//", solo devuelve objetos para nombres de hijos que coincidan con la expresión regular dada. Solo se utiliza el nombre base para la coincidencia:

@paths = path("/tmp")->children( qr/^foo/ );
# coincide con hijos como el comodín foo*

API actual disponible desde 0.028.

path("foo.txt")->chmod(0777);
path("foo.txt")->chmod("0755");
path("foo.txt")->chmod("go-w");
path("foo.txt")->chmod("a=r,u+wx");

Establece los permisos de archivo o directorio. El argumento puede ser un modo numérico, una cadena octal que comienza con un "0" o un subconjunto limitado del modo simbólico utilizado por /bin/chmod.

El modo simbólico debe ser una lista separada por comas de cláusulas de modo. Las cláusulas deben coincidir con "qr/\A([augo]+)([=+-])([rwx]+)\z/", que define los parámetros "quién", "op" y "perms" para cada cláusula. A diferencia de /bin/chmod, los tres parámetros son requeridos para cada cláusula, múltiples ops no están permitidos y los permisos "stugoX" no son compatibles. (Ver File::chmod para necesidades más complejas.)

API actual disponible desde 0.053.

path("/tmp/foo.txt")->copy("/tmp/bar.txt");

Copia la ruta actual al destino dado utilizando la función "copy" de File::Copy. Al tener éxito, devuelve el objeto "Path::Tiny" para el archivo recién copiado.

API actual disponible desde 0.070.

$obj = path("/tmp/foo.txt")->digest;        # SHA-256
$obj = path("/tmp/foo.txt")->digest("MD5"); # seleccionado por el usuario
$obj = path("/tmp/foo.txt")->digest( { chunk_size => 1e6 }, "MD5" );

Devuelve un resumen hexadecimal para un archivo. Se puede proporcionar un hash de opciones opcional. La única opción es "chunk_size". Si se proporciona "chunk_size", se leerán esa cantidad de bytes a la vez. Si no se proporciona, el archivo completo se cargará en memoria para calcular el resumen.

Cualquier argumento subsiguiente se pasa al constructor de Digest para seleccionar un algoritmo. Si no se proporcionan argumentos, el valor por defecto es SHA-256.

API actual disponible desde 0.056.

$name = path("/tmp/foo.txt")->dirname; # "/tmp/"

Devuelve la porción de directorio que obtendría al llamar a "File::Spec->splitpath( $path->stringify )" o "." para una ruta sin porción de directorio padre. Debido a que File::Spec es inconsistente, el resultado puede o no tener una barra inclinada final. Debido a esto, este método está obsoleto.

Un enfoque mejor y más consistente probablemente sea "$path->parent->stringify", que no tendrá una barra inclinada final, excepto para un directorio raíz.

Obsoleto en 0.056.

path("foo.txt")->edit( \&callback, $options );
path("foo.txt")->edit_utf8( \&callback );
path("foo.txt")->edit_raw( \&callback );

Estos son métodos de conveniencia que permiten "editar" un archivo utilizando un solo argumento de callback. Cargan el archivo utilizando "slurp", colocan el contenido dentro de una variable $_ localizada, llaman a la función de callback (sin argumentos) y luego escriben $_ (presumiblemente mutado) de nuevo en el archivo con "spew".

Se puede usar un hash de referencia opcional para pasar opciones. La única opción es "binmode", que se pasa a "slurp" y "spew".

"edit_utf8" y "edit_raw" actúan como sus respectivos métodos "slurp_*" y "spew_*".

API actual disponible desde 0.077.

path("foo.txt")->edit_lines( \&callback, $options );
path("foo.txt")->edit_lines_utf8( \&callback );
path("foo.txt")->edit_lines_raw( \&callback );

Estos son métodos de conveniencia que permiten "editar" las líneas de un archivo utilizando un solo argumento de callback. Iteran sobre el archivo: para cada línea, la línea se coloca en una variable $_ localizada, se ejecuta la función de callback (sin argumentos) y luego $_ se escribe en un archivo temporal. Cuando la iteración finaliza, el archivo temporal se renombra de forma atómica sobre el original.

Se puede usar un hash de referencia opcional para pasar opciones. La única opción es "binmode", que se pasa al método que abre los manejadores para leer y escribir.

"edit_lines_raw" es como "edit_lines" con un "binmode" almacenado en búfer de ":raw".

"edit_lines_utf8" es como "edit_lines" con un "binmode" almacenado en búfer :raw:encoding(UTF-8) (o ":raw:utf8_strict" con PerlIO::utf8_strict).

API actual disponible desde 0.077.

if ( path("/tmp")->exists ) { ... }     # -e
if ( path("/tmp")->is_dir ) { ... }     # -d
if ( path("/tmp")->is_file ) { ... }    # -e && ! -d

Implementa operaciones de prueba de archivos, lo que significa que el archivo o directorio realmente debe existir en el sistema de archivos. Hasta entonces, es solo una ruta.

Nota: "is_file" no es "-f" porque "-f" no es lo opuesto a "-d". "-f" significa "archivo plano", excluyendo enlaces simbólicos, dispositivos, etc. que a menudo se pueden leer igual que los archivos.

Use "-f" en su lugar si realmente quiere verificar un archivo plano.

API actual disponible desde 0.053.

$fh = path("/tmp/foo.txt")->filehandle($mode, $binmode);
$fh = path("/tmp/foo.txt")->filehandle({ locked => 1 }, $mode, $binmode);
$fh = path("/tmp/foo.txt")->filehandle({ exclusive => 1  }, $mode, $binmode);

API actual disponible desde 0.122.

$data = path("foo.txt")->slurp;
$data = path("foo.txt")->slurp( {binmode => ":raw"} );
$data = path("foo.txt")->slurp_raw;
$data = path("foo.txt")->slurp_utf8;

Lee el contenido del archivo en un escalar. Acepta una referencia de hash opcional que se puede usar para pasar opciones. La única opción disponible es "binmode", que se pasa a binmode() en el manejador utilizado para leer.

"slurp_raw" es como "slurp" con un "binmode" de ":unix" para una lectura rápida, sin búfer y en bruto.

"slurp_utf8" es como "slurp" con un "binmode" de :unix:encoding(UTF-8) (o ":unix:utf8_strict" con PerlIO::utf8_strict). Si Unicode::UTF8 0.58+ está instalado, se realizará una lectura sin búfer y en bruto en lugar de eso y el resultado se decodificará con "Unicode::UTF8". Esto es igual de estricto y es aproximadamente un orden de magnitud más rápido que usar :encoding(UTF-8).

Nota: "slurp" y similares bloquean el manejador de archivo antes de hacer slurp. Si planea hacer slurp de un archivo creado con File::Temp, asegúrese de cerrar otros manejadores o abrir sin bloqueo para evitar un interbloqueo:

my $tempfile = File::Temp->new(EXLOCK => 0);
my $guts = path($tempfile)->slurp;

Ver también "lines" si desea hacer slurp de un archivo en un array de líneas.

API actual disponible desde 0.004.

path("foo.txt")->spew(@data);
path("foo.txt")->spew(\@data);
path("foo.txt")->spew({binmode => ":raw"}, @data);
path("foo.txt")->spew_raw(@data);
path("foo.txt")->spew_utf8(@data);

Escribe datos en un archivo de forma atómica. El archivo se escribe en un archivo temporal en el mismo directorio, luego se renombra sobre el original. Una referencia de hash opcional puede usarse para pasar opciones. La única opción es "binmode", que se pasa a binmode() en el manejador utilizado para escribir.

"spew_raw" es como "spew" con un "binmode" de ":unix" para una escritura rápida, sin búfer y en bruto.

"spew_utf8" es como "spew" con un "binmode" de :unix:encoding(UTF-8) (o ":unix:utf8_strict" con PerlIO::utf8_strict). Si Unicode::UTF8 0.58+ está instalado, se realizará una escritura en bruto y sin búfer en los datos codificados con "Unicode::UTF8".

NOTA: dado que el archivo se escribe en un archivo temporal y luego se renombra, el nuevo archivo tendrá permisos basados en su umask actual. Esto es una característica para protegerlo de una condición de carrera que de lo contrario le daría permisos diferentes a los que podría esperar. Si realmente desea mantener las marcas de modo originales, use "append" con la opción "truncate".

API actual disponible desde 0.001.

path("foo/bar")->subsumes("foo/bar/baz"); # verdadero
path("/foo/bar")->subsumes("/foo/baz");   # falso

Devuelve verdadero si la primera ruta es un prefijo de la segunda ruta en un límite de directorio.

Esto *no* resuelve las entradas de directorio padre ("..") ni los enlaces simbólicos:

path("foo/bar")->subsumes("foo/bar/../baz"); # verdadero

Si tales cosas son importantes para usted, asegúrese de que ambas rutas se resuelvan al sistema de archivos con "realpath":

my $p1 = path("foo/bar")->realpath;
my $p2 = path("foo/bar/../baz")->realpath;
if ( $p1->subsumes($p2) ) { ... }

API actual disponible desde 0.048.

path("foo.txt")->touch;
path("foo.txt")->touch($epoch_secs);

Similar a la utilidad "touch" de Unix. Crea el archivo si no existe, o cambia los tiempos de modificación y acceso a la hora actual. Si el primer argumento son los segundos de la época, se utilizará.

Devuelve el objeto de ruta para que pueda encadenarse fácilmente con otros métodos:

# no fallará si foo.txt no existe

API actual disponible desde 0.015.

path("bar/baz/foo.txt")->touchpath;

Combina "mkdir" y "touch". Crea el directorio padre si no existe, antes de tocar el archivo. Devuelve el objeto de ruta como lo hace "touch".

Si necesita pasar opciones, use "mkdir" y "touch" por separado:

path("bar/baz")->mkdir( \%options )->child("foo.txt")->touch($epoch_secs);

API actual disponible desde 0.022.

path("/tmp")->visit( \&callback, \%options );

Ejecuta una función de devolución de llamada para cada hijo de un directorio. Devuelve una referencia de hash con cualquier estado acumulado durante la iteración.

Las opciones son las mismas que para "iterator" (que utiliza internamente): "recurse" y "follow_symlinks". Ambas valen falso por defecto.

La función de devolución de llamada recibirá un objeto "Path::Tiny" como primer argumento y una referencia de hash para acumular estado como segundo argumento. Por ejemplo:

# recopilar tamaños de archivos
my $sizes = path("/tmp")->visit(
    sub {
        my ($path, $state) = @_;
        return if $path->is_dir;
        $state->{$path} = -s $path;
    },
    { recurse => 1 }
);

Para mayor comodidad, el objeto "Path::Tiny" también estará localmente aliased como la variable global $_:

# imprimir rutas que coinciden con /foo/
path("/tmp")->visit( sub { say if /foo/
}, { recurse => 1} );

Si el callback devuelve una **referencia** a un escalar falso, la iteración se detendrá. Esto no es lo mismo que "podar" una búsqueda de directorios; solo detiene toda la iteración y devuelve la referencia al hash de estado.

# encuentra hasta 10 archivos de más de 100K
my $files = path("/tmp")->visit(
    sub {
        my ($path, $state) = @_;
        $state->{$path}++ if -s $path > 102400
        return \0 if keys %$state == 10;
    },
    { recurse => 1 }
);

Si quieres una iteración más flexible, usa un módulo como Path::Iterator::Rule.

API actual disponible desde 0.062.

$vol = path("/tmp/foo.txt")->volume;   # ""
$vol = path("C:/tmp/foo.txt")->volume; # "C:"

Devuelve la porción del volumen de la ruta. Esto es equivalente a lo que File::Spec daría de "splitpath" y, por lo tanto, generalmente es la cadena vacía en sistemas operativos similares a Unix o la letra de unidad para una ruta absoluta en "MSWin32".

API actual disponible desde 0.001.

SYNOPSIS

use Path::Tiny;
# Creando objetos Path::Tiny
my $dir = path("/tmp");
my $foo = path("foo.txt");
my $subdir = $dir->child("foo");
my $bar = $subdir->child("bar.txt");
# Se stringifica como ruta limpiada
my $file = path("./foo.txt");
print $file; # "foo.txt"
# Leyendo archivos
my $guts = $file->slurp;
   $guts = $file->slurp_utf8;
my @lines = $file->lines;
   @lines = $file->lines_utf8;
my ($head) = $file->lines( {count => 1} );
my ($tail) = $file->lines( {count => -1} );
# Escribiendo archivos
$bar->spew( @data );
$bar->spew_utf8( @data );
# Leyendo directorios
for ( $dir->children ) { ... }
my $iter = $dir->iterator;
while ( my $next = $iter->() ) { ... }

DESCRIPCIÓN

Este módulo proporciona una utilidad pequeña y rápida para trabajar con rutas de archivos. Es más amigable de usar que File::Spec y proporciona acceso fácil a funciones de varios otros módulos centrales de manejo de archivos. Su objetivo es ser más pequeño y rápido que muchas alternativas en CPAN, al tiempo que ayuda a las personas a hacer muchas cosas comunes de maneras consistentes y menos propensas a errores.

Path::Tiny no intenta funcionar para nada más que plataformas similares a Unix y Win32. Incluso entonces, podría fallar si intentas algo particularmente oscuro o tortuoso. (¡Rápido! ¿Qué significa esto: "///../../..//./././a//b/.././c/././"? ¿Y cómo difiere en Win32?)

Todas las rutas se fuerzan a tener barras inclinadas al estilo Unix. La stringificación del objeto te devuelve la ruta (después de cierta limpieza).

Los métodos de entrada/salida de archivos "flock" se manejan antes de leer o escribir, según corresponda (si es compatible con la plataforma y/o el sistema de archivos).

Los métodos *_utf8 ("slurp_utf8", "lines_utf8", etc.) operan en modo crudo. En Windows, eso significa que no tendrán traducción CRLF de la capa IO ":crlf". Instalar Unicode::UTF8 0.58 o posterior acelerará las situaciones de *_utf8 en muchos casos y es muy recomendable. Alternativamente, instalar PerlIO::utf8_strict 0.003 o posterior se usará en lugar del predeterminado :encoding(UTF-8).

Este módulo depende en gran medida de las capas PerlIO para un funcionamiento correcto y, por lo tanto, requiere Perl 5.008001 o posterior.

ENTORNO

PERL_PATH_TINY_NO_FLOCK

Si la variable de entorno "PERL_PATH_TINY_NO_FLOCK" está establecida a un valor verdadero, entonces flock NO se usará al acceder a los archivos (esto no se recomienda).

ADVERTENCIAS

Subclases no soportadas

Por velocidad, esta clase está implementada como un objeto basado en arrays y utiliza muchas llamadas directas a funciones internamente. No debes subclasarla y esperar que las cosas funcionen correctamente.

Expansión de tilde (obsoleto)

La expansión de tilde era una buena idea, pero no se puede aplicar fácilmente de manera consistente en toda la API. Fue una fuente de errores y confusión para los usuarios. Por lo tanto, está **obsoleta** y se desaconseja su uso. Las limitaciones del comportamiento existente y heredado son las siguientes.

La expansión de tilde solo ocurrirá si el **primer** argumento de "path" comienza con una tilde. **Ningún otro método realiza expansión de tilde en sus argumentos**. Si deseas expansión de tilde en los argumentos, debes envolverlos explícitamente en una llamada a "path".

path( "~/foo.txt" )->copy( path( "~/bar.txt" ) );

Si necesitas una tilde literal al principio, usa path("./~whatever") para que el argumento de "path" no comience con una tilde, pero la ruta aún resuelva al directorio actual.

El comportamiento de la expansión de tilde con un nombre de usuario para usuarios inexistentes depende de la salida de "glob" en el sistema.

Bloqueo de archivos

Si flock no es compatible en una plataforma, no se usará, incluso si se solicita el bloqueo.

En situaciones donde una plataforma normalmente admitiría el bloqueo, pero flock falla debido a una limitación del sistema de archivos, Path::Tiny tiene algunas heurísticas para detectarlo y advertirá una vez y continuará en modo inseguro. Si deseas que este fallo sea fatal, puedes hacer fatales las advertencias de la categoría 'flock':

use warnings FATAL => 'flock';

Ver advertencias adicionales a continuación.

NFS y BSD

En BSD, la implementación de flock de Perl puede no funcionar para bloquear archivos en un sistema de archivos NFS. Si se detecta, esta situación advertirá una vez, como se describe anteriormente.

Lustre

El sistema de archivos Lustre no soporta flock. Si se detecta, esta situación advertirá una vez, como se describe anteriormente.

AIX y bloqueo

AIX requiere un manejador de escritura para el bloqueo. Por lo tanto, las llamadas que normalmente abren un manejador de lectura y toman un bloqueo compartido en su lugar abrirán un manejador de lectura-escritura y tomarán un bloqueo exclusivo. Si el usuario no tiene permiso de escritura, no se usará ningún bloqueo.

utf8 vs UTF-8

Todos los métodos *_utf8 usan por defecto :encoding(UTF-8) -- ya sea como :unix:encoding(UTF-8) (sin búfer, para operaciones de archivo completas) o :raw:encoding(UTF-8) (con búfer, para operaciones línea por línea). Estos son estrictos contra la especificación Unicode y no permiten puntos de código Unicode o secuencias UTF-8 ilegales.

Desafortunadamente, :encoding(UTF-8) es muy, muy lento. Si instalas Unicode::UTF8 0.58 o posterior, ese módulo será utilizado por algunos métodos *_utf8 para codificar o decodificar datos después de una operación de entrada/salida cruda y binaria, lo cual es mucho más rápido. Alternativamente, si instalas PerlIO::utf8_strict, este se usará en lugar de :encoding(UTF-8) y también es muy rápido.

Si necesitas el rendimiento y puedes aceptar el riesgo de seguridad, "slurp({binmode => ":unix:utf8"})" será más rápido que :unix:encoding(UTF-8) (pero no tan rápido como "Unicode::UTF8").

Ten en cuenta que los métodos *_utf8 leen en modo **crudo**. No hay traducción CRLF en Windows. Si debes tener traducción CRLF, usa los métodos de entrada/salida regulares con un binmode apropiado:

$path->spew_utf8($data);                            # crudo
$path->spew({binmode => ":encoding(UTF-8)"}, $data; # LF -> CRLF

Capas IO predeterminadas y el pragma open

Si tienes Perl 5.10 o posterior, los métodos de entrada/salida de archivos ("slurp", "spew", etc.) y los métodos de apertura de manejadores de alto nivel ( "filehandle", "openr", "openw", etc.) respetan las codificaciones predeterminadas establecidas por el modificador o la configuración lexical de apertura del llamador. Para UTF-8, esto es casi seguro más lento que usar los métodos dedicados "_utf8" si tienes Unicode::UTF8 o PerlIP::utf8_strict.
